## 手动发布一次预览

完成某个代码分支的修改后，可用 EAS CLI 发布当前 JavaScript / 静态资源更新：

~~~sh
eas update --auto
~~~

--auto 会以当前分支名称作为 EAS Update branch。成功后终端会显示该次更新的 EAS Dashboard 链接；把链接发给评审者，评审者在页面点 Preview 会看到二维码，然后用已安装且兼容的 Development Build 扫码打开。

## 每次提交自动生成预览

EAS Workflows 可在每次代码提交时发布一条预览更新。先配置项目，再在仓库根目录创建：

~~~text
.eas/workflows/publish-preview-update.yml
~~~

一个最小工作流示例：

~~~yaml
name: Publish preview update

on:
  push:
    branches: ['*']

jobs:
  publish_preview_update:
    name: Publish preview update
    type: update
    params:
      branch: ${{ github.ref_name || 'test' }}
~~~

该工作流会为每个分支上的提交发布 Update。也可以手动触发：

~~~sh
eas workflow:run publish-preview-update.yml
~~~

只要开发构建的 native runtime 与更新兼容，评审者无需安装新的原生 binary，就能查看当前分支页面。改了 native module、权限或原生配置时，仍需新建 build。

## 关键名词

- **Preview update**：用于评审的 EAS Update，通常对应某个分支或 PR 的 JS / assets 状态。
- **EAS Dashboard**：Expo 网页端项目界面，展示更新详情、预览二维码等。
- **EAS Workflow**：由 .eas/workflows/*.yml 描述的云端自动化步骤。
- **Branch**：EAS Update 的发布目标名称；--auto 会将当前代码分支名用于预览发布。
- **Compatibility / 兼容性**：只有 runtimeVersion 与原生构建匹配的更新，才能被那个 Development Build 加载。
