# 051｜向已安装应用发送 OTA 更新

**翻页：**[上一页：App Store 元数据](./050-App-Store元数据.md) · [目录](./README.md) · [下一页：发布 Expo Web 应用](./052-发布Expo-Web应用.md)

**官方页面：**[Send over-the-air updates](https://docs.expo.dev/deploy/send-over-the-air-updates/)

**SDK 56 API 校对：**[expo-updates v56](https://docs.expo.dev/versions/v56.0.0/sdk/updates/) 推荐版本 `~56.0.26`。OTA 只替换 JS / 静态资源，不会加入新原生模块。

## 什么是 OTA Update

Over-the-air update（无线更新）用于向已安装的 app 发布兼容的 JavaScript bundle 和资源文件。若改动涉及 native module、原生配置或 runtime compatibility，则必须重新构建原生应用，OTA 不能替代新原生包。

## 配置更新服务

若此前发布过预览、或已创建 EAS Build，项目可能已经设置过更新配置。否则运行：

~~~sh
eas update:configure
~~~

完成初始化后，要先创建新的 Android / iOS build，让新的原生 binary 包含 updates URL 和 runtimeVersion 配置，然后再发布 OTA。

## 向 production channel 发布

~~~sh
eas update --channel production
~~~

这会创建一条 Update 并分发给 eas.json 中配置为 production channel 的兼容构建。

测试方式：在设备上强制关闭并重新打开 app 两次。第一次启动通常下载更新；重新启动后再加载新 bundle。

## 用 EAS Workflow 自动发布

示例 workflow 在 main branch 每次提交时发布 production 更新：

~~~yaml
name: Send updates

on:
  push:
    branches: ['main']

jobs:
  send_updates:
    name: Send updates
    type: update
    params:
      channel: production
~~~

手动触发：

~~~sh
eas workflow:run send-updates.yml
~~~

EAS Update 还可设置 rollout、优化 bundle / assets，并用 EAS Dashboard 检查目标渠道发布结果。

## 关键名词

- **OTA**：应用已安装后从网络获取更新，无需每次重新上架。
- **Channel**：构建所订阅的更新通道；发送到不同 channel 的 update 会分发给不同用户群 / build。
- **Runtime version**：原生 binary 与 JS bundle 的兼容约束。
- **EAS Update**：Expo 托管的更新发布服务及 CLI / Dashboard 工作流。
