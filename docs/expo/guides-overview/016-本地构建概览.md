**官方页面：**[Build locally: Overview](https://docs.expo.dev/guides/local-app-overview/)

## 为什么要本地构建

Expo 可以交给 EAS 云端 Build，也可以用本机 Android SDK / Xcode 编译。当团队要修改 native code、快速验证平台专属行为、离线编译、自己管理上传凭证，或使用自定义构建缓存 / 源码版 Expo Module 时，本地 Build 更方便。

本地 build 不是 EAS 的替代品；两者可在一个项目里配合：日常调试在本机，给团队分享或生产分发时用 EAS。

## 本机工具链

- Android 本机构建需安装 Android Studio 与 Android SDK / build tools。
- iOS 本机构建需 macOS 和 Xcode。
- 由 Expo Prebuild 管理的项目没有 `android/` / `ios/` 目录时，首次 `expo run` 会生成原生工程。

## Debug build 与 Release build

快速调试用 Expo CLI：

```sh
npx expo run:android
npx expo run:ios
```

这两个命令编译 native binary、安装到指定模拟器 / 设备并启动 Metro。如果只是改 JS / TS，之后一般只需运行 `npx expo start`，按 `A` / `I` 启动已安装客户端，不需要重新编译原生项目。

Release / production build 还需要签名凭证。Xcode / Android Studio 或 CLI 可生成签名产物，然后单独向商店提交；没有签名的本地 Release variant 不能直接上架。

## 本地构建的扩展项

- 可用 EAS 或自建 build cache provider 复用本地构建缓存。
- Android 默认使用预编译 Expo Modules 提升 Gradle 迭代速度；如需修改模块源码，可对一个或所有模块选择退出预编译、转为从源码编译。
- 有多个 Android product flavors 时，`expo run:android` 支持 platform-specific `--variant` 和自定义 `--app-id`。
- iOS 需要 simulator / device 不同配置时，CLI 参数与 Xcode Scheme 要匹配。

## 关键名词

- **Debug build**：包含调试能力、连接 Metro 的开发 binary。
- **Release build**：优化后的安装包，仍需签名才能分发到商店。
- **Native toolchain**：Android SDK / Gradle 或 Xcode / CocoaPods 等平台编译工具。
- **Precompiled Expo Module**：EAS / 本地构建可以直接链接的预编译 Expo 原生模块，提高 Android 初次及重复构建速度。
- **Product flavor**：Android 工程内为 dev / free / paid 等应用变体设置的 Gradle 构建变体。
