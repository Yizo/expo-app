## 环境变量是什么

环境变量是构建工具、开发机或云端运行时提供给程序的 key-value 配置，可切换开发 / 测试 / 生产 API 地址等。Expo CLI 会从根目录 `.env` 系列文件读取以 `EXPO_PUBLIC_` 开头的值，并在打包客户端代码时内联替换。

```dotenv
# .env
EXPO_PUBLIC_API_URL=https://staging.example.com
EXPO_PUBLIC_FEATURE_DEMO=true
```

业务代码必须通过静态属性访问 `process.env`：

```tsx
const apiUrl = process.env.EXPO_PUBLIC_API_URL;

function ExampleButton() {
  return <Button title="发送" onPress={() => fetch(apiUrl!)} />;
}
```

计算属性、解构赋值不会被 Expo CLI 静态内联：

```ts
process.env['EXPO_PUBLIC_API_URL']; // 不会被内联
const { EXPO_PUBLIC_API_URL } = process.env; // 不会被内联
```

客户端 JS bundle 对用户可读，所以 `EXPO_PUBLIC_` 中不能放私钥、数据库密码或服务端 token。它适用于 public API base URL 等客户端本就可见的配置。

## `.env` 文件优先级与 Git 忽略

Expo 使用标准 `.env` 文件解析，可用 `.env.local` 覆盖本机开发值。要避免个人机器地址写入源码仓库，通常把本地文件放进 `.gitignore`：

```gitignore
.env*.local
```

本文只是说明忽略规则，不执行 Git 操作。若误将私钥放进公开 `.env`，移除文件并不能撤销已经泄漏的密钥，仍需轮换凭证。

## 不要用 NODE_ENV 选择环境文件

Expo 文档建议避免用 `NODE_ENV` 在不同 `.env` 文件间切换，因为 `expo export` 会强制使用 production；通过 `eas update` 调用 export 的流程也可能得到 production 配置。可使用 EAS Environment 的 `eas env:pull`，或脚本有控制地替换 `.env.local`。

## 禁用 Expo 的自动注入

需要排错时可以分别关闭 `.env` 加载和客户端内联：

```sh
EXPO_NO_DOTENV=1 npx expo start
EXPO_NO_CLIENT_ENV_VARS=1 npx expo start
```

这两项作用不同：前者不把 `.env` 注入 CLI 进程；后者不把公开 `process.env.EXPO_PUBLIC_*` 替换进客户端 bundle。

## 与 EAS 的关系

EAS Build 用 Metro 生成 app binary 内的 JS bundle，所以可读取 build job 有权访问的 `.env` / EAS 环境值。EAS Update 也在本地或 CI 生成 bundle，构建时读取可用值。云端 jobs 通常读不到本地未提交的 `.env.local`；多环境项目可用 EAS Environment 管理构建值。

## 从其它方案迁移

从 `react-native-config` 迁移时，把 JavaScript 使用的变量加上 `EXPO_PUBLIC_` 前缀，直接读 `process.env`：

```diff
- API_URL=https://api.example.com
+ EXPO_PUBLIC_API_URL=https://api.example.com
```

```diff
- import Config from 'react-native-config';
- const apiUrl = Config.API_URL;
+ const apiUrl = process.env.EXPO_PUBLIC_API_URL;
```

从 `babel-plugin-transform-inline-environment-variables` 迁移时，把普通变量名改成 `EXPO_PUBLIC_...`，移除 Babel 插件，并在修改后清 Metro cache：

```js
module.exports = function (api) {
  api.cache(true);
  return { presets: ['babel-preset-expo'] };
};
```

从 direnv 迁移时，将 JS app 用到的值放入 `.env` 并改为 `EXPO_PUBLIC_` 前缀。其他仅供 Node 脚本或 config 使用的本机变量，可继续由 shell / dynamic app config 读取。

## 关键名词

- **Environment variable**：部署或启动时注入的键值配置。
- **Inline / 内联**：构建阶段把变量值直接写进 JS bundle，运行时就不是读取系统环境，而是已嵌入的字符串。
- **Static property reference**：在源码中明确写出 `process.env.EXPO_PUBLIC_NAME` 这种访问，使 Metro 能定位并替换。
- **`.env.local`**：通常用于机器私有的覆盖文件；不应把密钥误当成客户端安全存储。
- **NODE_ENV**：工具链的标准构建模式值，不适合同时担当业务环境切换器。
