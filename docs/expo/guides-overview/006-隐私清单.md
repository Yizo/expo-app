**时效说明：**Expo 官方页面说明本指南仍在更新中。Apple 要求与识别原因可能变化；这份笔记解释 Expo 配置路径，提交 App Store 前需检查最新要求。

## Privacy Manifest 是什么

iOS 的 `PrivacyInfo.xcprivacy` 是项目原生资源，用来声明应用或第三方库是否调用 Apple 标记为 sensitive / required-reason 的 API，以及使用 API 的理由。文档列出的 API 类别包括 UserDefaults、文件时间戳、系统启动时间、磁盘空间与活动键盘。

它不是 Privacy Policy（隐私政策）：清单是构建产物中的技术声明，隐私政策则面向用户描述数据做法。

## 在 Expo app config 中配置

采用 CNG 时，可在 `expo.ios.privacyManifests` 填写 required-reason 类别和对应 reason code：

```json
{
  "expo": {
    "name": "My App",
    "slug": "my-app",
    "ios": {
      "privacyManifests": {
        "NSPrivacyAccessedAPITypes": [
          {
            "NSPrivacyAccessedAPIType": "NSPrivacyAccessedAPICategoryUserDefaults",
            "NSPrivacyAccessedAPITypeReasons": ["CA92.1"]
          }
        ]
      }
    }
  }
}
```

`NSPrivacyAccessedAPITypes` 是 API 类别数组；每项要标明 API 类型与用途理由。不要照抄示意中的 `UserDefaults` / reason 作为自己应用的理由，应按应用和依赖的实际调用核对 Apple 要求。

完成依赖升级时可运行 `npx expo install --fix`，让 SDK 依赖落在当前 SDK 对应版本范围。

## 既有 React Native 原生工程

如果团队直接维护 `ios/`，可以在 Xcode 创建 Privacy manifest 文件并添加到应用 target。CNG 项目则把内容放在 Expo app config，由 Prebuild 写入生成工程。两种方式都要避免手工文件与 app config 同时声明同一项造成维护混乱。

Expo SDK / Pod 库可能各自附带自己的 `PrivacyInfo.xcprivacy`。Expo 指南提醒 App Store 提交流程未必完整解析静态 CocoaPods 依赖中的所有文件；需检查依赖目录中的清单并按要求把理由纳入应用清单。提交构建后，Apple 也可能反馈遗漏项，再据反馈补充配置。

## 测试

构建 iOS app 并送 App Store review 或 TestFlight 外部审核，Expo 指南说若缺少 required reason Apple 会发送提醒。此步骤适合确认清单是否完整，但要以当前苹果审核与隐私规则为最终依据。

## 关键名词

- **Privacy Manifest**：随 iOS app 打包的隐私技术声明文件 `PrivacyInfo.xcprivacy`。
- **Required-reason API**：Apple 要求说明使用理由的系统 API 类别。
- **Reason code**：将 API 使用目的映射到 Apple 允许理由的代码。
- **Target**：Xcode 工程中独立构建的应用或扩展单元；清单需要归属到正确 target。
- **CocoaPods**：iOS 常用原生依赖管理工具；Expo iOS SDK 库可能通过 Pods 提供原生实现。

## 官方代码主题覆盖

源页唯一 JSON 代码主题 `expo.ios.privacyManifests.NSPrivacyAccessedAPITypes` 已提供改写示例；包含 required reason 的类型与理由字段。源页还展示 `npx expo install --fix`，并说明已有 RN 项目手工创建文件、检查依赖包内清单与提交审核测试的做法。
