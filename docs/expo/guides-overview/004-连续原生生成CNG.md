## CNG 是什么

**Continuous Native Generation（CNG，连续原生生成）**是从 app config、依赖版本、生成参数和插件反复生成 `android/` 与 `ios/` 的工程管理模式。团队主要维护生成规则和自定义项，而不是长期手工维护大批模板原生代码。

**Prebuild** 是 Expo 对 Android / iOS 实现 CNG 的工具。它会根据 Expo SDK 配套模板、Config Plugin 和 Autolinking 处理原生工程。CNG 是可选工作流，并不妨碍直接使用 Expo SDK 或 EAS。

## 常用命令

```sh
# 生成或同步 Android 与 iOS 工程
npx expo prebuild

# 先删除旧原生目录，再从头生成
npx expo prebuild --clean

# 只生成一个平台；也可使用 android
npx expo prebuild --platform ios

# 本地编译原生客户端
npx expo run:android
npx expo run:ios
```

原生目录不存在时，`expo run` 会先对对应平台执行 Prebuild。改动 app config 或增加原生依赖后，要重新同步并重建；只改 JS / TS 业务代码通常不需要重新生成原生项目。

### 依赖安装、包管理器与模板开关

Guide 还展示可跳过特定 RN / React 依赖自动改版、强制指定安装器、跳过安装及指定自定义原生模板：

```sh
npx expo prebuild --skip-dependency-update react-native,react
npx expo prebuild --npm
npx expo prebuild --no-install
npx expo prebuild --template ./my-template.tgz
```

Prebuild 会从 lockfile 判断 npm / Yarn / pnpm / Bun；`--npm`、`--yarn`、`--pnpm` 可强制安装器，`--no-install` 可在快速测试生成流程时跳过安装。页面给出的命令也有 `yarn expo`、`pnpm expo`、`bun expo` 等价形式。

## CNG 与 EAS Build 如何配合

如果工程没有 `android/` 和 `ios/`，EAS Build 会在云端编译前生成原生工程；如果已有两个目录，EAS Build 为避免覆盖手工改动不会自动 Prebuild。Web 在浏览器中运行，没有需要 Prebuild 生成的原生项目。

新建 CNG 项目一般把生成的 Android / iOS 目录加入 `.gitignore`；Expo 模板通常已处理。文档也展示 `.easignore` 场景。此示意是应写入忽略文件的文本，不是要在此执行任何 Git 命令：

```gitignore
/android
/ios
```

## Clean 与原生改动

普通 `prebuild` 可能在现有生成文件上叠加结果；插件不幂等或工程状态变化时，可能得到意外结果。`--clean` 会删掉现有原生目录并重建，所以会清除只手工写在这些目录里的改动。若使用 CNG，应把修改沉淀在 app config / Config Plugin 后再清理生成。

在 CI 中使用 `--clean` 时官方说明不会展示本地未提交变更提醒；本地检查可由 `EXPO_NO_GIT_STATUS=1` 环境变量关闭。这里解释配置项，不执行 Git 操作。

## Prebuild 的边界和副作用

- Expo Prebuild 当前直接生成 Android 与 iOS；Web 不需要它。
- Prebuild 会修改 `package.json` 的 scripts 与依赖字段；最终文件应检查后再纳入团队工作流。
- 原生依赖通过 Autolinking 自动发现；需要额外权限或平台设置时，依赖通常需要 Config Plugin。
- Prebuild 对现有纯手工维护的 Brownfield 原生工程不适合作为整体生成器，因为会覆盖原生自定义内容。
- 原生运行时回调更适合 Expo Modules API lifecycle listener；普通 plist / Manifest 修改可用 Config Plugin。
- 也可通过 `--template` 传入自定义模板，但模板要与 Prebuild 内部假设保持兼容，升级成本更高。

## 关键名词

- **Prebuild**：读取 Expo 项目配置并生成 / 同步平台原生目录的 CLI 阶段。
- **Autolinking**：构建时发现已安装原生包并把它们接进 Xcode / Gradle 工程。
- **Orphaned code**：依赖已删除但遗留在原生工程中的配置或代码，来源难以追溯。
- **Brownfield app**：已有完整原生应用，正在逐步嵌入 React Native / Expo 的工程。
- **Idempotent plugin**：重复执行仍产生相同结果、不重复追加配置的插件。
