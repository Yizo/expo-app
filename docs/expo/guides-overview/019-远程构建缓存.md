## 远程缓存如何缩短本地编译

本机运行 `npx expo run:android` 或 `npx expo run:ios` 时，CLI 根据项目 fingerprint 查找可复用的原生 binary：找到后下载并启动；找不到则正常编译，再把结果上传 Provider。后续相同配置可减少重复编译等待。

这里缓存的是**原生 app build 产物**，不是 Metro 热更新 bundle，也不替代 EAS Build。

## 使用 EAS Build 作为 Provider

先把官方 Provider 安装为开发依赖。常见 package manager 可使用：

```sh
npx expo install eas-build-cache-provider --dev
yarn expo install eas-build-cache-provider --dev
pnpm expo install eas-build-cache-provider --dev
bun expo install eas-build-cache-provider --dev
```

Windows 下如需把 CLI 参数传给 Expo CLI，可用分隔符：

```sh
npx expo install eas-build-cache-provider -- --dev
yarn expo install eas-build-cache-provider -- --dev
pnpm expo install eas-build-cache-provider -- --dev
bun expo install eas-build-cache-provider -- --dev
```

在 app config 启用内建 EAS Provider：

```json
{
  "expo": {
    "buildCacheProvider": "eas"
  }
}
```

SDK v56 reference 可确认 `buildCacheProvider` 配置字段存在；当前 Guide 的缓存 provider 包版本仍需按 CLI / SDK 配套关系核对。

## 自定义 Provider 插件

自定义插件需要实现查找缓存、上传 build 两个函数；fingerprint 算法可选：

```ts
type Platform = 'android' | 'ios';
type BuildCacheProviderPlugin<Options = unknown> = {
  resolveBuildCache(
    input: {
      projectRoot: string;
      platform: Platform;
      runOptions: RunOptions;
      fingerprintHash: string;
    },
    options: Options
  ): Promise<string | null>;
  uploadBuildCache(
    input: {
      projectRoot: string;
      buildPath: string;
      platform: Platform;
      runOptions: RunOptions;
      fingerprintHash: string;
    },
    options: Options
  ): Promise<string | null>;
  calculateFingerprintHash?(
    input: { projectRoot: string; platform: Platform; runOptions: RunOptions },
    options: Options
  ): Promise<string | null>;
};
```

`resolveBuildCache` 命中后回可下载 URL，未命中回 `null`；`uploadBuildCache` 上传成功回缓存 URL，失败回 `null`。两个必需 hook 都会收到项目路径、平台、构建参数和 fingerprint；上传 hook 额外收到文件路径。

典型的 provider package 文件结构：

```text
provider/
  src/index.ts
  tsconfig.json
provider.plugin.js
```

`provider/tsconfig.json` 指定 Expo Module Scripts 提供的 plugin 编译配置；从 `src` 编译并输出到 `build`：

```json
{
  "extends": "expo-module-scripts/tsconfig.plugin",
  "compilerOptions": {
    "outDir": "build",
    "rootDir": "src"
  },
  "include": ["./src"],
  "exclude": ["**/__mocks__/*", "**/__tests__/*"]
}
```

空实现可先验证 CLI 能否加载插件。下面的两个 hook 目前都回 `null`，因此它本身不会完成真实缓存读写：

```ts
import { type BuildCacheProviderPlugin } from '@expo/config';

const provider: BuildCacheProviderPlugin = {
  resolveBuildCache: async () => {
    console.log('正在查询已有构建');
    return null;
  },
  uploadBuildCache: async () => {
    console.log('准备上传本地构建');
    return null;
  },
};

export default provider;
```

项目根目录的 `provider.plugin.js` 指向 TypeScript 编译结果：

```js
module.exports = require('./provider/build');
```

在自定义 Provider package 中提供编译脚本后，可用官方示例中的命令启动 TypeScript watch build：

```sh
npm run build provider
```

Example app 可在 app config 中指向插件文件，并通过 `options` 传入自定义配置；options 会作为 hook 的第二个参数：

```json
{
  "expo": {
    "buildCacheProvider": {
      "plugin": "./provider.plugin.js",
      "options": {
        "bucketName": "my-app-builds"
      }
    }
  }
}
```

## 在本地验证 Provider

进入 Example 项目，分别运行 Android / iOS 本机命令。代码示例的日志用于确认插件 hook 被调用；真实 Provider 还需实现 URL 生成、上传 / 下载和错误处理：

```sh
cd example
npx expo run:android
npx expo run:ios
```

## 缓存使用范围

- Provider 只被本机 `npx expo run:android` / `npx expo run:ios` 咨询；`eas build` 总会创建新产物，不走这层缓存。
- iOS 真机 build 因 provisioning profile 与设备绑定，不会查询或上传共享缓存；iOS Simulator build 可参与缓存。
- 若 `appVersionSource: "remote"`，Android `versionCode` / iOS `buildNumber` 存在 EAS 服务器而非项目源文件里，因此不属于 fingerprint。缓存 binary 可能保留生成时写入的 build number。

## 关键名词

- **Provider**：负责查询、上传 build 缓存的适配层；可使用 EAS 或实现自有存储。
- **Fingerprint**：项目和构建输入的摘要；只有摘要匹配才可安全复用 binary。
- **Build cache**：已编译原生 app 的可下载产物。
- **Plugin options**：通过 app config 传入自定义 Provider 的配置对象。
- **Simulator build**：运行于模拟器的原生 binary，不含真实设备 provisioning 限制。
