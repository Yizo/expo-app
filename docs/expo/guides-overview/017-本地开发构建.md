## 本地 build 做什么

`expo run` 使用开发机的 Android SDK / Xcode 编译原生客户端并安装到模拟器 / 设备，然后启动 Metro 为它加载 JS / TS。首次执行会先生成 `android/` 或 `ios/` 目录；目录已存在时不会自动重做 Prebuild。

```sh
npx expo run:android
npx expo run:ios
```

可以传 `--device` 选择连接的手机或模拟器。Yarn / pnpm / Bun 项目可使用 `yarn expo run:*`、`pnpm expo run:*`、`bun expo run:*`。

## Debug / Release variant

以上默认生成 Debug build。`--variant release`（Android）或 `--configuration Release`（iOS）可编译未签名 Release 产物；它们还不能上传应用商店，签名步骤见下一页。

Android 从 SDK 54 起还可使用 `--variant debugOptimized`，在保持开发体验的同时更快执行 JS，适合较贴近 Release 的性能验证。该能力只对应 Android Gradle variant。

## 首次编译之后的 Metro 循环

Binary 安装后，只改 JS / TS 时不用每次重编 native code，单独启动 Metro 并打开 app：

```sh
npx expo start
```

也可使用 `yarn expo start` / `pnpm expo start` / `bun expo start`，然后按 `A` / `I` 启动已安装的 Android / iOS app。新增 native package、改 config plugin、改原生源文件后要重新执行 `expo run:android|ios`。

## Development Client

安装 `expo-dev-client` 后的 Debug build 会包含自己的开发者工具 UI，并可加载 Expo Go 不包含的项目原生模块：

```sh
npx expo install expo-dev-client
npx expo run:android
```

通过 `expo install` 选择 SDK 对应版本，避免 npm 上最新版与本项目 Expo SDK 不匹配。

## Android Product Flavors

已有多个 Android app variant 时，可用 `--variant` 指定 variant，并在启动时用 `--app-id` 指定对应 application ID：

```sh
npx expo run:android --variant freeDebug
npx expo run:android --variant paidDebug
npx expo run:android --variant freeDebug --app-id dev.example.app.free
```

Variant / application ID 必须与 Gradle 工程里声明的一致。源码页还指向 EAS `--local` 在开发者自有机器上运行 cloud-build 流程的文档。

## 关键名词

- **Development Build**：带 `expo-dev-client` 的 app-specific 开发客户端。
- **Metro bundler**：提供开发 JS bundle 的服务器；单纯业务代码变动由 Metro 推给 app。
- **Variant / flavor**：Android 可并存的多个 build 类型 / 产品差异，例如 Free / Paid。
- **Unsigned release build**：以 Release 配置编译但尚未被商店凭证签名的文件。
- **Build vs bundle**：前者编译 native binary，后者处理 JS / assets；日常 JS 改动只需 bundle。
