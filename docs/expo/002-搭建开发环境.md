## 选择运行设备

官方建议尽早用真实设备开发，因为真实设备能展示用户实际看到的系统界面、权限提示、字体和交互。文档同时列出 Android 设备、iOS 设备、Android Emulator 和 iOS Simulator 作为运行目标。

- **真实设备**：手里的 Android 手机或 iPhone/iPad。通过本地网络或隧道连接电脑上的开发服务器。
- **模拟器 / 仿真器**：电脑上模拟手机操作系统的开发工具。Android Emulator 提供 Android 运行环境；iOS Simulator 随 Xcode 提供 iOS 模拟环境。它们方便调试，但最终仍应在目标设备上检查。

页面把“目标设备”和“开发方式”分成两步：前者决定应用跑在哪里，后者决定应用使用哪套原生壳和功能。

## 选择 Expo Go 或 Development Build

Expo Go 与 Development Build 都能连接 Expo 开发服务器、加载正在编写的 JS/TS 代码。两者差异在于手机上安装的原生应用不同。

| 方式 | 是什么 | 适用场景与限制 |
| --- | --- | --- |
| **Expo Go** | 一个已安装在手机上的通用 Expo 客户端，内含一组预先编译好的原生模块。你的 JS 项目由它加载运行。 | 适合学习和快速体验 Expo；可用能力受 Expo Go 已打包的模块限制，不能把任意自定义原生代码临时塞进去。官方不建议把它当作生产项目的最终运行容器。 |
| **Development Build（开发构建）** | 为当前应用生成的原生调试版本，包含 Expo 开发工具，也可以包含项目需要的自定义原生模块。 | 适合真实项目开发，尤其是需要 Expo Go 未内置的原生库时。它仍是开发版本，不等于提交商店的正式发布包。 |

对 React Web 开发者来说，可以把 Expo Go 想成“预先装好一批 RN 原生能力的测试容器”；Development Build 则是“为自己的 app 编译的开发客户端”。两者都不是浏览器页面。若新增了原生模块，通常需要重新编译自己的 Development Build，单纯刷新 JS 不能把新原生代码补进旧安装包。

## 安装 Android Expo Go

官方页面说明可通过 Google Play 安装 Expo Go，也可以从 Expo 下载页选择版本：[Expo Go 下载页](https://expo.dev/go)。

本页的其余设备选项以图卡展示，没有额外命令代码。v56 支持 Android 7+ 和 iOS 16.4+；需要本地编译时，SDK v56.0.0 参考页列出 compile / target SDK 36、Xcode 26.4+。安装对应平台工具前先核对项目实际采用本地编译还是 EAS 云构建。

## 关键名词

- **开发服务器**：电脑上的 Expo CLI 服务，打包并提供当前 JS/TS 项目给设备或模拟器。
- **原生二进制 / native build**：编译后的 Android 或 iOS 应用安装包，内含平台代码与原生模块。改普通 JS 页面通常可快速刷新；改原生依赖、权限或配置时往往需要重新构建。
- **Development Build**：自己的应用的开发版原生二进制，装有调试工具；它弥合了 Expo Go 的模块限制和正式应用之间的差异。
- **Expo Go**：Expo 提供的通用原生客户端，主要用于快速试验。它的能力集合由该客户端自身包含的原生模块决定。
