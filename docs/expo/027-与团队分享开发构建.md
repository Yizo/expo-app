**官方页面：**[Share a development build with your team](https://docs.expo.dev/develop/development-builds/share-with-your-team/)

## 分享的 Development Build 是什么

当一个开发构建准备好后，可以让队友在设备上安装同一份原生二进制。Android / iOS 内部分发允许指定哪些设备可安装，适合多人并行检查同一原生构建，也能同时分发多个版本供评审。

## 方式一：分享安装 URL

每个构建会生成唯一分享 URL，其中包含安装该 build 的说明。可发给队友，也可直接在测试设备上打开。

若 iOS 构建完成后又注册了新的测试设备，通常要为新设备再生成一个 Development Build，才能把该设备加入内部签名配置。

## 方式二：EAS Dashboard 下载

将队友引导到 EAS Dashboard 中该构建的详情页；队友可从那里下载构建产物到对应设备。

## 方式三：EAS CLI 安装

队友先用创建该构建的 Expo 账号登录，再运行：

```sh
eas build:run --profile development
```

如果构建 profile 名称不是 `development`，将 `--profile` 的值换成该构建使用的名称。

## iOS 设备注意事项

- iOS 16 及以上真机如果尚未启用 Developer Mode，需要先打开开发者模式；企业分发流程除外。
- 若要给新测试设备添加 Ad Hoc profile，可用 `eas build:resign` 重新对现有 `.ipa` 签名并加入设备。这样可复用当前产物，避免为了补一个设备重新从头编译。

## 关键名词

- **Build artifact**：已完成的 Android / iOS 构建文件，可供测试设备安装。
- **Internal distribution**：面向团队 / 内部测试设备的分发方式，不是公开商店发布。
- **Ad Hoc provisioning**：在 iOS 上将应用签名并限制为已登记设备安装的配置。
- **Re-sign**：用新的签名 / 设备配置重新签署现有 `.ipa` 文件，不重新编译 JavaScript 和原生源代码。
