# 024｜在 EAS Workflows 中运行 E2E 测试

**翻页：**[上一页：用 EAS Workflows 部署到 Production](./023-部署到Production.md) · [目录](./README.md) · [下一页：EAS Build 导言](./025-EAS-Build导言.md)

**官方页面：**[Run E2E tests on EAS Workflows with Maestro](https://docs.expo.dev/eas/workflows/examples/e2e-tests/)

**版本说明：**此官方示例用 Maestro flow 编写 UI 端到端检查，再由 EAS Build 生成 emulator / simulator binary 并交给 Maestro job。此处仅记录配置，没有安装 Maestro、构建应用或访问 GitHub。

## E2E 测试与 Maestro

端到端（E2E）测试会在真实或模拟设备上操作完整应用，验证界面和主要用户流程。Maestro 的 YAML flow 可以启动 app、点击文本和断言屏幕上出现内容。

测试前，EAS project 需链接 GitHub repo 并已配置 EAS Workflows。测试 flow 放在项目根目录的 .maestro，与 eas.json 同级。

首页流程：启动示例 app 并确认欢迎文字出现。

```yaml
appId: dev.example.e2etest
---
- launchApp
- assertVisible: 'Welcome!'
```

第二条 flow 打开 Explore tab，展开“File-based routing”折叠区，并检查对应说明：

```yaml
appId: dev.example.e2etest
---
- launchApp
- tapOn: 'Explore.*'
- tapOn: '.*File-based routing'
- assertVisible: 'This app has two screens.*'
```

测试 ID 必须换成自己项目的 Android application ID / iOS bundle identifier；flow 中的文字定位也应与自己的真实 UI 对应。

## 本地运行 Maestro（可选）

安装 Maestro CLI 并将 app 安装到 Android emulator 或 iOS Simulator 后，逐个执行 flow：

```sh
maestro test .maestro/expand_test.yml
maestro test .maestro/home.yml
```

该步骤可先验证 YAML selectors，再交给云端 workflow 自动跑。

## E2E 测试 build profile

EAS Maestro job 需要已编译 binary：Android 用可直接安装的 APK，iOS simulator 用 .app。profile 可不要求商店签名凭证：

```json
{
  "build": {
    "e2e-test": {
      "withoutCredentials": true,
      "ios": {
        "simulator": true
      },
      "android": {
        "buildType": "apk"
      }
    }
  }
}
```

## Pull Request workflow

Android workflow 先 build，再由 Maestro job 通过 build_id 安装产物并运行两个 flow：

```yaml
name: e2e-test-android

on:
  pull_request:
    branches: ['*']

jobs:
  build_android_for_e2e:
    type: build
    params:
      platform: android
      profile: e2e-test

  maestro_test:
    needs: [build_android_for_e2e]
    type: maestro
    params:
      build_id: ${{ needs.build_android_for_e2e.outputs.build_id }}
      flow_path:
        - .maestro/home.yml
        - .maestro/expand_test.yml
```

iOS simulator workflow 的形状相同，只将 build 平台改为 iOS：

```yaml
name: e2e-test-ios

on:
  pull_request:
    branches: ['*']

jobs:
  build_ios_for_e2e:
    type: build
    params:
      platform: ios
      profile: e2e-test

  maestro_test:
    needs: [build_ios_for_e2e]
    type: maestro
    params:
      build_id: ${{ needs.build_ios_for_e2e.outputs.build_id }}
      flow_path:
        - .maestro/home.yml
        - .maestro/expand_test.yml
```

手动触发可用 eas workflow:run；配置了 GitHub 连接后，每个 Pull Request 会自动触发测试：

```sh
eas workflow:run .eas/workflows/e2e-test-android.yml
```

Workflow dashboard 显示 build job 与每个 Maestro flow 的日志及通过 / 失败结果。

## 关键名词

- **E2E / end-to-end**：从用户操作入口到最终 UI / 数据结果的完整流程测试。
- **Maestro Flow**：按步骤执行点击、输入、断言的 YAML 测试脚本。
- **appId**：Maestro 在目标设备上定位待测应用的原生应用 ID。
- **APK / .app**：Android 安装包与 iOS Simulator 可运行的 app bundle。
- **needs / build_id**：让测试 job 等待上游 Build 完成，并取得它的二进制产物。
