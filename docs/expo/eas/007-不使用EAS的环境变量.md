## 本机与其它部署工具

不使用 EAS 也可以在项目本地 `.env` 文件管理变量，或由部署系统 / shell 在进程启动时注入。Expo CLI 会依标准 `.env` 规则载入配置；任何供前端 JS 读取的值要以 `EXPO_PUBLIC_` 开头，构建时会被内联替换。

需要敏感值时应只留在 server process / server-side Route。`.env` 文件中的变量会按标准优先级载入，代码中的 `process.env.EXPO_PUBLIC_NAME` 在 bundle 生成时替换；`node_modules` 中的第三方包代码不会被替换。

## EAS 命令与本地 `.env`

EAS 云端命令只能读取随构建任务提交的文件；被忽略的本地 `.env.local` 不会自动上传。若要在不使用 EAS Environment 的流程中让云端 Job 读取 `.env`，必须明确把正确文件提供给构建任务；切忌把私钥放在前端会内联的变量中。需要 Secret 时应使用云端安全变量机制或部署平台的服务端 secret。

## EAS Hosting 特例

使用 `.env` 配合 EAS Hosting 时，`EXPO_PUBLIC_` 值可用于浏览器和服务端；未带此前缀的值只在服务端代码可读。运行 Web export 前要确保当前 `.env` 对应目标环境：

```sh
npx expo export --platform web
eas deploy --environment production
```

export 时公开值进入浏览器代码；服务器环境值由部署阶段上传到 API Routes。改了 `.env` 后需要重新 export 和 deploy 才会产生新版本。

## 关键名词

- **Dotenv**：用 KEY=VALUE 格式表达环境变量的文件约定。
- **Process environment**：操作系统注入给当前进程的变量表。
- **Server code**：在 Hosting / API Route 云端执行、不会发送给终端用户的逻辑。
- **Ignored file**：被项目同步或版本管理排除的本地文件；云端 job 通常不会接收到它。
