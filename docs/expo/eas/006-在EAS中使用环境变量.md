# 006｜在 EAS Build、Update、Hosting 与 Workflows 中使用变量

**官方页面：**[Using environment variables in EAS](https://docs.expo.dev/eas/environment-variables/usage/)

## EAS Build

在 `eas.json` profile 中配置 `environment`，构建时读取该环境的变量：

```json
{
  "build": {
    "preview": { "environment": "preview" },
    "production": { "environment": "production" }
  }
}
```

如果省略，EAS 根据 build profile 分发类型和 developmentClient 配置推导环境；为避免 staging / production 值串用，生产 profile 建议显式写环境。平台 build worker 还会提供系统变量，例如 `CI`、`EAS_BUILD`、`EAS_BUILD_PLATFORM`、build ID / profile / project ID、工作目录和 NPM / Maven / CocoaPods cache URL。它们用于 job 日志和原生构建脚本，不会自动写入客户端 JS。

## EAS Update

SDK 55+ 发布更新必须显式选择服务器环境（本地 SDK56 在该范围内）：

```sh
eas update --environment production
```

指定后，bundle 使用被选中的 EAS 变量，项目内 `.env` 不参与该云端更新 job；Secret 不可用于客户端 bundle。Build 和 Update 都传同一个环境，有助于保证他们打包的公开配置一致。

## EAS Hosting

Router API Routes 可在服务器读取未带 `EXPO_PUBLIC_` 的变量；浏览器代码则必须用 `EXPO_PUBLIC_`，因为所有客户端变量都会在 `npx expo export` 阶段写入 JS bundle。EAS Hosting 的部署变量支持 Plain text / Sensitive，Secret 不能部署到 Hosting：

```sh
# 本机准备 client bundle（EXPO_PUBLIC_* 会被内联）
npx expo export --platform web

# 再把 API Route 的 server values 一起部署
eas deploy --environment production
```

部署是不可变快照；改变 EAS 环境变量后，要重新 export 并 deploy 才会进入新 deployment。客户端代码不可保存私钥；API Route 在 server 环境中才适合使用服务端密钥。

## EAS Workflows

不同 job 有默认 environment：Build 使用 `eas.json` profile，Submit 继承被提交的 build，Maestro job 默认 preview，其它 update / fingerprint / deploy / custom job 默认 production。最好显式设定 `environment`，与构建所用 profile 同步：

```yaml
name: Preview
jobs:
  build_preview:
    type: build
    params:
      platform: ios
      profile: preview
  publish_preview_update:
    needs: [build_preview]
    type: update
    environment: preview
    params:
      branch: preview
```

另一个常见关系是先计算 fingerprint，再用同一 production 环境构建：

```yaml
name: Fingerprint and build
jobs:
  fingerprint:
    type: fingerprint
    environment: production
  build_ios:
    needs: [fingerprint]
    type: build
    params:
      platform: ios
      profile: production
```

Build hook 中可以使用 `set-env` 给同一个 build job 后续步骤设置值。需要在一条 EAS 命令期间给 bash 子命令提供变量，也可用 `eas env:exec`：

```sh
set-env EXAMPLE_ENV "example value"
eas env:exec production 'echo $APP_VARIANT'
```

后续 job 用 Node.js `process.env.VARIABLE_NAME` 或 shell `$VARIABLE_NAME` 读取。Fingerprint / Update 等 job 的 environment 要和对应 build 环境一致，否则会将更新配置和错误的 binary 匹配。

## 关键名词

- **EAS Build worker**：云端编译机器；其 `EAS_BUILD_*` 变量只描述当前构建任务。
- **Client-side inlining**：构建时把公开值写入 Web / native JS bundle。
- **API Route**：Expo Router 中以 `+api.ts` 结尾、在服务端执行的请求处理文件。
- **Immutable deployment**：部署产物生成后固定；变量变化后需要重新 export 和 deploy。
- **Job environment**：Workflow 单个 job 从 EAS 哪个环境取得变量。
