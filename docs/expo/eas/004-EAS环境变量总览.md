## 为什么把变量放在 EAS

本机 `.env` / `.env.local` 通常不会上传到远程云构建，因此 EAS Build、Workflows 和部署环境看不到你电脑上的设置。EAS Environment Variables 把云端配置放在 Expo 项目 / 账号中，再按环境和 visibility 控制哪些任务可以使用。

Quick start 的流程是：在 EAS 建 production API URL，给 `eas.json` 的 production profile 指定环境，发布 update 时也显式选择 production；部署 Web 时先同步变量、导出静态资源，再部署：

```sh
eas env:set --name EXPO_PUBLIC_API_URL \
  --value https://api.example.com \
  --environment production \
  --visibility plaintext
```

```json
{
  "build": {
    "production": { "environment": "production" }
  }
}
```

```sh
eas update --environment production
eas env:pull --environment production
npx expo export --platform web
eas deploy --environment production
```

Web 部署时，先导出客户端 JS / HTML，之后再发布服务器 API Routes；`EXPO_PUBLIC_` 值在导出时会进入浏览器 bundle。

## 环境、范围、值类型、可见性

- **Environment**：默认有 `development`、`preview`、`production` 三个变量集；同名变量可以按环境有不同值。自定义环境按官方页面需符合相应计划权限。
- **Scope**：Project 环境变量只属于当前 app；Account 级变量可供账号下多个项目复用，并和项目变量共同提供给 job。
- **Type**：普通字符串或文件变量；文件型将上传的证书、`google-services.json` 等在构建 worker 上以路径交给 job。
- **Visibility**：Plain text 可在网站、CLI、日志读取；Sensitive 会在 Build / Workflow 日志遮盖，但可在允许的 UI / CLI 场景查看；Secret 只能由 EAS server job 读取，本地 CLI 和网站不可取回。

即使是 Secret，如果最终被嵌进 app 客户端 bundle，也不能继续保密。秘密类型适合让云端任务读取私钥，而不是保护客户端代码中的值。

## SDK 55+ 的 EAS Update 环境要求

官方文档说明 SDK 55 或以上的 `eas update` 必须带 `--environment`；本地 SDK56 属于此范围。此参数指定更新 bundle 所用的云端环境变量集，并避免构建、Update 与 Web deploy 使用不同配置。

## 关键名词

- **Scope**：变量所属项目或 Expo 账号。
- **Visibility**：EAS UI / CLI / 日志 / worker 可否读取或显示变量。
- **File variable**：变量的值是一份上传文件，云端任务拿到的是临时路径。
- **EAS Environment**：具有独立变量集合的 deployment / build 环境名。
- **Client-side variable**：打包进 JS 的变量，即使来自 Secret，也不再是秘密。
