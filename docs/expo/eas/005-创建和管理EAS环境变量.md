# 005｜创建和管理 EAS 环境变量

**翻页：**[上一页：EAS 环境变量总览](./004-EAS环境变量总览.md) · [目录](./README.md) · [下一页：在 EAS 中使用变量](./006-在EAS中使用环境变量.md)

**官方页面：**[Create and manage environment variables in EAS](https://docs.expo.dev/eas/environment-variables/manage/)

## 创建变量要决定的三件事

1. **Environment**：development / preview / production；同名变量可以按环境有不同值。
2. **Scope**：project 只给当前项目，account 可供账号下多个项目复用。
3. **Visibility**：Plain text、Sensitive、Secret，按数据是否要离开 EAS server 决定。

可以在 Expo Dashboard 的 Project Settings → Environment variables 添加变量；EAS CLI 操作示例：

```sh
# 给 preview 环境增加客户端可见的 API endpoint
eas env:set --name EXPO_PUBLIC_API_URL \
  --value https://staging.example.app \
  --environment preview \
  --visibility plaintext

eas env:list --environment preview
```

## 在客户端与 app config 中读取

名称以 `EXPO_PUBLIC_` 开头的变量可在客户端静态读取：

```tsx
const endpoint = process.env.EXPO_PUBLIC_API_URL;
```

它会写进 bundle，不能当秘密。`APP_VARIANT` 等不带此前缀的变量可在动态 `app.config.js` / `.ts` 中决定应用名、bundle ID 或 Android package：

```js
const variant = process.env.APP_VARIANT ?? 'production';
const isDev = variant === 'development';

export default {
  name: isDev ? 'Example Dev' : 'Example',
  ios: { bundleIdentifier: isDev ? 'com.example.dev' : 'com.example' },
  android: { package: isDev ? 'com.example.dev' : 'com.example' },
};
```

EAS 的 Secret 不可在本地 EAS CLI 动态解析 app config；若配置必须在本机解析，应使用至少可被 CLI 读取的 visibility，并确保值本身可安全读取。

## 文件变量与本机开发

Google Services JSON 可作为 Secret file variable 上传，然后在 app config 指向它。开发机本地也可有自己的文件路径作为 fallback：

```js
export default {
  android: {
    googleServicesFile:
      process.env.GOOGLE_SERVICES_JSON ?? './google-services.json',
  },
};
```

把本地密钥文件保持在忽略列表里，避免误传到仓库；云端 build 使用 EAS file variable 提供临时文件。

CLI 管理操作还包括创建 / 更新 `eas env:set`、查看 `eas env:list`、删除 `eas env:delete`、将 EAS 值下载为本地 `.env` 的 `eas env:pull`，自定义环境用自己的 environment name。例如：

```sh
eas env:delete --name EXPO_PUBLIC_OLD_API_URL --environment production
eas env:pull --environment development --path .env.local
eas env:set --name EXPO_PUBLIC_API_URL \
  --value https://staging.example.app \
  --environment staging --visibility plaintext
```

`eas env:pull` 不会下载 Secret，因为 CLI 不能读云端秘密；dashboard 也可导出可读变量文件。

## 自定义环境

默认三个环境适合多数项目；复杂发布流程可以建立 `staging` 等自定义环境。官方页面指出自定义环境只对 Enterprise / Production 计划开放。给至少一个变量绑定自定义名后，它会在变量表中可选。

## 关键名词

- **Project variable / Account variable**：项目内变量和可跨项目复用的账号变量。
- **APP_VARIANT**：常用来选择 dev / preview / production app 的不同包名与品牌。
- **Secret file**：将被 job 创建到工作目录以外临时位置的文件型秘密，不是客户端 bundle 内容。
- **Fallback**：本地开发可使用的配置备用路径，云端 build 时由 Secret file 环境覆盖。
