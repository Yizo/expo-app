# 038｜排查 Expo 运行时问题

**官方页面：**[Debugging runtime issues](https://docs.expo.dev/debugging/runtime-issues/)

## 先分清开发期和生产期问题

开发时可以连接本地 Metro、查看源码与调用栈；正式版崩溃通常只留下日志和崩溃报告。先判断错误发生于哪种运行环境，再选择工具。

## 开发期：缩小复现范围

1. 读错误消息和 Stack Trace，先找项目自身的首个出错文件和位置。
2. 搜索报错关键词，查看官方文档、论坛和 Issue 是否有类似情况。
3. 回退到能运行的版本，从最近改动开始一次恢复一部分，找出是哪段代码引发问题。
4. 复杂功能可以复制到最小 Expo 项目试跑，再逐步加回状态管理、网络请求或原生依赖。
5. 用 DevTools breakpoint / `console.log` 检查逻辑是否执行及当时的变量值。

**Minimal Reproducible Example（最小复现）**指删除无关功能、仍能稳定重现错误的最小代码。它能把“应用看起来坏了”缩窄到具体调用或依赖。

## 需要调原生代码时

如果错误来自 Swift / Kotlin、原生模块或系统 API，可把 Expo 项目生成成原生目录并用 Android Studio / Xcode 调试。Android 和 iOS 可分别用 Expo CLI 生成对应目录：

| 包管理器 | Android | iOS |
| --- | --- | --- |
| npm / npx | `npx expo prebuild -p android` | `npx expo prebuild -p ios` |
| Yarn | `yarn expo prebuild -p android` | `yarn expo prebuild -p ios` |
| pnpm | `pnpm expo prebuild -p android` | `pnpm expo prebuild -p ios` |
| Bun | `bun expo prebuild -p android` | `bun expo prebuild -p ios` |

macOS 上可以这样打开 IDE 项目：

```sh
open -a "/Applications/Android Studio.app" ./android
xed ios
```

Android 在 Android Studio 编译后可附加原生 debugger；iOS 需要 macOS 和 Xcode，可用 Xcode / LLDB 检查原生进程。若这次原生调试只是临时生成目录，结束后可删掉生成的 `android/` 或 `ios/` 目录，恢复由 Expo Prebuild 管理；若保留并手动维护，就需要自行处理原生库升级。

## 收集系统级日志

JavaScript 错误未必包含崩溃原因。原生日志能提供 Android 系统、iOS 系统与原生模块的事件：

```sh
adb logcat
```

Android 可在设备 / 模拟器执行 `adb logcat`。iOS 可在 Xcode 的 Devices and Simulators 窗口选择设备，再打开 macOS Console 应用查看日志。

## 生产崩溃

优先想办法本机复现；然后依次查看：

- Android Play Console 的崩溃报告。
- iOS TestFlight / App Store Connect 在 Xcode 中的 Crashes Organizer。
- 设备 `adb logcat` 或 Console 的系统日志。
- 若配置 Sentry、Bugsnag 等错误报告服务，查看对应的堆栈、设备信息和面包屑。

也可以在本地模拟生产 JS 环境，排查开发模式隐藏的问题：

```sh
npx expo start --no-dev --minify
```

`--no-dev` 关闭开发模式，`--minify` 使用正式 JS 包相同的压缩方式。

如果只有老设备崩溃，考虑内存或帧率瓶颈，使用性能 profiler；React Native DevTools 看 JS 性能，Android Studio / Xcode 看原生性能。
