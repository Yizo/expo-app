**SDK 56 API 校对：**[`expo-dev-client` v56](https://docs.expo.dev/versions/v56.0.0/sdk/dev-client/)；推荐版本 `~56.0.26`。

## 什么是 Development Build

Expo Go 是一款通用测试容器，预先编译了一批 Expo 原生模块。**Development Build（开发构建）**则是为自己的应用编译出的调试版本，可以把项目所需的原生库、应用配置和 `expo-dev-client` 工具放在一起。

适合准备做真实应用、需要 Expo Go 没有的原生模块或原生配置时使用。它包含调试菜单、网络请求检查和启动器，可在不同开发服务器 / 已发布更新之间切换。它仍是开发版本，并不是交给应用商店的正式发布包。

## 三种构建方式

三种方式最终都会生成同一类 Development Build，区别在于谁负责编译，以及电脑需要哪些工具：

| 方式 | 编译地点 | 电脑上的要求 | 账号 |
| --- | --- | --- | --- |
| 本地 Expo CLI | 在本机通过 Android Studio / Xcode 编译 | 安装目标平台的 Android Studio 或 Xcode。可在 iOS Simulator 或 Android Emulator 调试。官方指出，这是没有付费 Apple Developer 账号时，把开发构建装到 iPhone 的方式。 | 本地 Android / iOS Simulator 构建不要求 Expo 账号。 |
| EAS Build | Expo 云端构建机 | 无需本地安装原生编译工具；从任意 OS 发起 iOS 构建。 | 需要登录 Expo / EAS。 |
| EAS CLI 本地构建 | EAS Build 在本机执行（`--local`） | 仍要安装本机原生工具链。EAS 继续管理签名和构建 profile。 | 需要 Expo 账号和 EAS CLI 登录。 |

## 安装开发客户端

在项目根目录加上 `expo-dev-client`。本地 v56 参考页推荐 `~56.0.26`；通过 `expo install` 由当前 SDK 选择兼容版本：

| 包管理器 | 命令 |
| --- | --- |
| npm / npx | `npx expo install expo-dev-client` |
| Yarn | `yarn expo install expo-dev-client` |
| pnpm | `pnpm expo install expo-dev-client` |
| Bun | `bun expo install expo-dev-client` |

创建新项目后若使用普通 Expo 模板，通常会走 CNG / Prebuild。现有 RN CLI 项目、没有使用 CNG 的项目需额外配置 Expo 模块和原生工程。

## 本地编译与安装

使用对应平台的命令在 Android Emulator 或 iOS Simulator 本地编译：

| 包管理器 | Android | iOS |
| --- | --- | --- |
| npm / npx | `npx expo run:android` | `npx expo run:ios` |
| Yarn | `yarn expo run:android` | `yarn expo run:ios` |
| pnpm | `pnpm expo run:android` | `pnpm expo run:ios` |
| Bun | `bun expo run:android` | `bun expo run:ios` |

`expo run:*` 默认在运行中的模拟器安装应用。实体 Android 设备需要 USB 连接并开启 USB debugging，再添加 `--device`。实体 iPhone 需要打开 Developer Mode、在 Expo 配置中设置唯一的 `ios.bundleIdentifier`，再添加 `--device`。

如果尚未生成 `android/` / `ios/` 目录，Expo 构建命令会自动执行 Prebuild，然后编译、安装并启动开发服务器。

## JS 修改与原生修改的区别

- **只改 TypeScript / JavaScript**：不必重建原生 app，重启 / 使用热更新的开发服务器即可。
- **新增或升级带原生代码的依赖**：要重新生成原生目录并构建 Development Build，因为已安装的二进制里还没有该库的原生实现。
- **修改 `app.json` 或升级 Expo SDK**：同样需要把配置同步到原生工程并重新编译。

当项目按 CNG 管理原生目录时，可以先按包管理器运行 `expo prebuild --clean`，再重新 `expo run:android` 或 `expo run:ios`。`--clean` 会重新生成原生目录；如果项目手工维护原生工程，不应把这一步当成每次 JS 调试流程的一部分。

| 包管理器 | 重新生成目录 | 之后重新编译 |
| --- | --- | --- |
| npm / npx | `npx expo prebuild --clean` | `npx expo run:android` / `npx expo run:ios` |
| Yarn | `yarn expo prebuild --clean` | `yarn expo run:android` / `yarn expo run:ios` |
| pnpm | `pnpm expo prebuild --clean` | `pnpm expo run:android` / `pnpm expo run:ios` |
| Bun | `bun expo prebuild --clean` | `bun expo run:android` / `bun expo run:ios` |

常规 JS 开发时，对应命令是 `npx expo start`、`yarn expo start`、`pnpm expo start` 或 `bun expo start`。

如果开发构建未安装 `expo-dev-client`，需要用 `npx expo start --dev-client` 明确让开发服务器连接自定义开发客户端。

## 使用 EAS 构建的任务步骤

官方页面也给 AI 代理提供三种任务模板；这些是复制给代理的提示词，不是本页要求直接执行的命令。

1. **用本机工具构建**：让代理装 `expo-dev-client`，检查是否安装 Android / iOS 工具链，再按目标平台执行 `expo run:android` 或 `expo run:ios`。实体设备要增加 `--device`。构建安装后执行 `expo start`。
2. **在 EAS 云端构建**：让代理装 `expo-dev-client`，确认 `eas-cli` 与账号登录状态，若缺少则创建 development profile；若目标是 iOS Simulator，在 profile 加 `ios.simulator: true`。随后按用户指定平台运行：

   ```sh
   eas build --platform <platform> --profile development
   ```

   页面提示代理先完成配置并停下来向用户确认，用户同意后再创建云构建；完成后安装到指定模拟器并启动 `expo start`。
3. **由 EAS CLI 在本机运行构建**：步骤与云端相似，但使用 `--local`：

   ```sh
   eas build --platform <platform> --profile development --local
   ```

   生成 `.apk` / `.app` 后安装到模拟器，再启动开发服务器。

## 关键名词

- **Development Build**：为当前应用编译的开发版原生容器，可加载项目 JS，并包含自定义原生模块。
- **`expo-dev-client`**：开发客户端工具包，提供启动器、调试菜单和网络检查等开发功能。
- **EAS Build**：Expo 的云端 / 本地构建服务，支持构建 profile、凭证和签名流程。
- **Profile**：`eas.json` 中一组构建选项，例如 development / preview / production。
- **CNG / Prebuild**：从 app config 生成 Android / iOS 工程；生成之后才有平台原生代码可编译。
- **`ios.bundleIdentifier`**：iOS 应用在 Apple 生态里的唯一标识。
