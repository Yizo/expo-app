**官方页面：**[Debugging and profiling tools](https://docs.expo.dev/debugging/tools/)

> 该指南未版本化。SDK 56 配套 React Native 0.85（见 [SDK v56.0.0 参考页](https://docs.expo.dev/versions/v56.0.0/)）。本页调试步骤以当前 Expo 指南为准；React Native DevTools 需要 Hermes，具体 JavaScript 引擎仍应按项目配置确认。

## 先识别错误来源

React Native 应用由 JavaScript 运行逻辑和 iOS / Android 原生运行时共同组成。若异常来自 Swift、Kotlin 或原生库，JavaScript DevTools 未必能看到；若来自 React、状态或接口请求，则原生 IDE 未必能直接找到原因。根据错误边界选择工具。

## Developer Menu

Developer Menu（开发者菜单）内置于 Expo Go 和 Development Build，可访问重载、元素检查、性能监控、DevTools 等功能。

| 平台 / 连接方式 | 打开方法 |
| --- | --- |
| 连接 Expo CLI 的模拟器 / 真机 | 在运行 Expo CLI 的终端按 `M`。 |
| Android 真机（无线） | 垂直摇动设备。 |
| Android Emulator / USB 设备 | `Cmd + M` 或 `Ctrl + M`；也可运行 `adb shell input keyevent 82`。 |
| iOS 真机（无线） | 摇动手机，或三指触碰屏幕。 |
| iOS Simulator / USB 设备 | `Ctrl + Cmd + Z` 或 `Cmd + D`。 |

菜单常用项：

- **Reload**：重新加载 app（Fast Refresh 开启时一般不需要手动点）。
- **Go Home**：回到 Expo Go 或 Dev Client 的主页。
- **Performance Monitor**：看 RAM、JS heap、视图数量，以及 UI / JS 线程帧率。
- **Element Inspector**：查看控件位置和交互区域。
- **Open DevTools**：打开 React Native DevTools。
- **Fast Refresh**：保存 JS / TS 文件后自动刷新模块。

**UI Thread** 负责原生界面绘制；**JS Thread** 负责大部分 React 逻辑、网络调用和事件回调。若只有 JS FPS 下降而 UI FPS 正常，常见线索是 JavaScript 线程过忙。

## React Native DevTools

React Native 0.76 起，React Native DevTools 取代 Chrome DevTools。项目需在 Hermes 上运行；启动后在 Expo CLI 终端按 `J` 打开。

可用面板：

- **Console**：运行时日志，也能执行 JS 表达式。
- **Sources**：源文件与断点。
- **Network**：Expo 场景可查看 fetch、媒体资源和部分原生模块请求及响应。
- **Memory**：检查 JS 内存、拍取 heap snapshot。
- **Components**：查看组件树、props、style。
- **Profiler**：录制并分析 JS 渲染性能；当前指南说明仅 debug build 可用，且 profiler 记录暂不做 source map symbolication。原生性能需用 Android Studio / Xcode。

### 在断点处暂停

在 Sources 面板单击行号设置断点，或在源文件临时加入：

```ts
debugger;
```

到达断点后应用会暂停，能查看当前 scope 的变量，并在 Console 中执行代码。遇到已捕获异常时，也可启用 Pause on caught exceptions 检查异常首次出现的位置。

## VS Code 调试

Expo Tools VS Code 扩展提供内建 debugger 连线能力，目前文档标为 Alpha。连接运行中的 app 后，打开 Command Palette（macOS `Cmd + Shift + P`，Windows/Linux `Ctrl + Shift + P`），运行 **Expo: Debug ...**，随后可设置断点、观察变量、执行 Console 命令。

## 老版 React Native Debugger

独立 React Native Debugger 依赖 Remote JS Debugging；React Native 0.73 起弃用该流程，而且它与 Hermes 不兼容。SDK 50 及以上应使用 React Native DevTools；此旧版工具主要供 SDK 49 及更早项目参考。

旧版说明曾提供 macOS Homebrew 安装 `brew install react-native-debugger` 的方式；安装后将其端口设为 8081，运行 Expo 服务器并在 Developer Menu 选择 **Debug remote JS**。不能把旧 Debugger 步骤套到运行 Hermes 的项目里，包括使用 SDK 56 且配置为 Hermes 的构建。

## 其它调试入口

- **Rozenite**：React Native DevTools 插件框架，可把第三方调试界面以面板接入 DevTools，也可开发自己的 Rozenite 插件。
- **生产错误报告**：Sentry、Bugsnag 等服务能提供发布版本的堆栈、设备信息和实时告警。
- **网络代理**：可用 Charles、Proxyman、mitmproxy、Fiddler 等代理分析网络流量；其行为与 DevTools 中的 Expo Network 面板不同。

## 关键名词

- **Dev Menu**：运行中开发客户端 / Expo Go 的调试操作菜单。
- **Hermes**：React Native JavaScript 引擎；当前指南中的 React Native DevTools 依赖 Hermes。SDK 56 的配套 RN 版本为 0.85，但是否使用 Hermes 仍以项目配置为准。
- **Remote JS Debugging**：已弃用的旧式远程调试方式，不能用于 Hermes app。
- **Heap Snapshot**：JavaScript 堆内存快照，可用于比较对象保留和排查 JS 内存泄漏。
- **Symbolication**：把编译 / 压缩代码位置还原到源码位置的映射过程。
