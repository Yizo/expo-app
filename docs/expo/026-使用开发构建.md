## 每次改 JS 不必重编译原生应用

Development Build 已安装在设备或模拟器之后，大部分 TypeScript / JavaScript 修改只要由 Expo 开发服务器重新打包即可。只有原生模块、原生配置等发生变化时才需要重建 Development Build。

## 启动项目

在项目根目录启动 Metro / Expo 开发服务器，选择当前的包管理器命令：

| 包管理器 | 命令 |
| --- | --- |
| npm / npx | `npx expo start` |
| Yarn | `yarn expo start` |
| pnpm | `pnpm expo start` |
| Bun | `bun expo start` |

随后：

- Android Emulator 按 `A`，iOS Simulator 按 `I`，在对应模拟器打开项目。
- 在真机上用系统相机或二维码扫描工具读取终端二维码，打开已安装的 Development Build。

## Development Build 启动器

从手机主屏幕直接打开自己的开发构建，会先看到 launcher 启动器。若它能在本地网络中发现 Metro，或 Expo CLI 与开发构建都登录了同一个 Expo 账号，可以直接连接；否则扫描 CLI 显示的二维码。

启动器可以在本地开发服务器与远端服务器之间切换；也可以打开不同的 EAS Update 版本。它让一个已安装的原生 app binary 重用不同 JS 更新，而无需每切换开发服务器就重新编译。

## 何时要重建

如果项目新增含原生代码的依赖（例如 `expo-secure-store`），必须重新构建并安装开发客户端。该原生实现不会因执行 `expo install` 就自动加入当前已经安装的 app binary。

TypeScript / JS 页面内容变更则通过热刷新观察，不需要重新编译原生应用。

## 打开开发者菜单

在 Expo CLI 或开发构建中按 `Cmd + D`（macOS）或 `Ctrl + D`（Windows/Linux）；手机 / 平板也可摇动设备。开发者菜单可访问调试工具、查看运行信息并管理当前开发会话。

## 关键名词

- **Native code change**：会改变 Android / iOS 编译产物的代码或配置，例如含 Swift / Kotlin 实现的依赖。
- **JS bundle**：Metro 根据当前 JavaScript / TypeScript 项目即时生成的代码包。
- **Launcher**：开发客户端打开后连接本地 / 远端开发服务器和更新渠道的启动器界面。
- **EAS Update**：发布给已安装原生 app 的兼容 JavaScript 更新；若含新的原生模块，仍需新的原生构建。
- **Developer menu**：运行中的 Expo / React Native app 的调试菜单入口。

## 官方代码主题覆盖
