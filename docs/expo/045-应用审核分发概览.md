## 三种评审途径

Expo 文档列出三种把预览版本交给团队和测试者的方法：应用商店测试轨道、EAS 内部分发、已安装 Development Build 配合 EAS Update。

| 方法 | 产物 / 用法 | 主要限制 |
| --- | --- | --- |
| 应用商店测试轨道 | Android 上传 AAB 到 Google Play Console；iOS 上传到 App Store Connect / TestFlight。测试者从商店客户端安装。 | 必须是 Release Build，不能用 Development Build。商店上传与审核流程会花时间。 |
| EAS Internal distribution | EAS Build 生成可安装 APK 或 iOS Ad Hoc app，并提供唯一链接。 | iOS Ad Hoc 分发要将测试设备纳入签名 profile。完成后可立即下载安装，不需等待商店审核。 |
| Development Build + EAS Update | 先通过内部分发安装开发构建，再发布兼容的 JS / 静态资源 Update；设备在原生兼容时可直接预览变化。 | 只能更新兼容当前 runtimeVersion 的 JS / assets；新增原生模块仍需新构建。 |

Expo Go 是入门 playground，不适合作为正式应用评审容器。

## Google Play Beta

Google Play 测试轨道包括 Internal、Closed、Open：

- Internal track 最多可邀请 100 位测试者。
- Closed track 由团队邀请，Open track 可公开加入，允许更大范围测试。
- 上传 Android App Bundle（AAB），设置轨道，再通过 email 或链接邀请用户；测试者从 Play Store 安装。
- Google Play Console 可收集反馈与崩溃报告。

## TestFlight

TestFlight 需要付费 Apple Developer 账号。Internal testing 可将同一开发者团队中最多 100 名成员纳入测试组；External testing 最多 10,000 人，可通过邮件或公开链接邀请。

所有 TestFlight 测试构建都要上传 App Store Connect，并经过自动处理后才能分享；External testing 还要通过面向 Beta 的 App Review。这个 Beta 审核与正式上架审核是两个流程。

## EAS 内部分发与 OTA 预览

内部分发 URL 可由设备直接打开安装，包含 Android APK 或 iOS ad hoc 签名 app。Development Build 安装后，可以从 EAS Dashboard 打开某个兼容更新，也可以在 CI 中随 Pull Request 自动发布预览。通过 `eas update` 更新 JS / assets，通常几秒就能让团队看到新预览，不需要重新上传到商店。

## 关键名词

- **Release Build**：用于商店或正式测试轨道的发布构建，不包含开发菜单。
- **AAB**：Android App Bundle，上传至 Google Play 的 Android 发布格式。
- **Internal distribution**：EAS 提供的团队内部安装链接，和 Play / App Store 测试轨道不同。
- **Ad Hoc provisioning**：iOS 内部分发签名，限定可安装该构建的已登记设备。
- **OTA Update**：原生二进制之后发布的 JavaScript / 静态资源更新；native code 不会通过 OTA 被替换。
- **Runtime version**：限制哪些原生构建可接收某条 EAS Update 的兼容标识。
