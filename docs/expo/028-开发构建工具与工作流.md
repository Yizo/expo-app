## 让设备连接开发服务器：Tunnel URL

默认开发服务器使用局域网连接；网络防火墙或路由器阻挡设备时，可为 `expo start` 加 `--tunnel` 生成公网可访问的转发 URL：

```sh
npx expo start --tunnel
```

Tunnel 也便于开发中邀请他人查看页面，但通常比本地 LAN 慢。

## 发布一个测试更新

`eas update` 会把当前 JavaScript 与静态资源打成 OTA 更新并放到 Expo 更新服务。已安装的兼容 Development Build 能读取更新，不要求测试者切换 Git 分支，也不需要开发者一直开着本地服务器。

### 手动打开某个更新

开发构建启动器可以手动填入更新 URL。基本形式为：

```text
https://u.expo.dev/<project-id>?channel-name=<channel-name>
```

Project ID 可在 app config 的 `expo.updates.url` 字段找到；EAS 渠道可用 `eas channel:list` 查看。

### 用 Deep Link 打开更新

开发客户端 Deep Link 的基本形式为：

```text
<scheme>://expo-development-client/?url=<URL-encoded-manifest-url>
```

`scheme` 默认使用 `exp+<slug>`；manifest URL 是前面的 `https://u.expo.dev/...` 地址经过 URL 编码后的值。CI / E2E 首次启动可将 `disableOnboarding=1` 加到要编码的更新 URL 中；`disableFab=1` 隐藏开发者菜单按钮，`disableAutoLaunch=1` 阻止启动时自动打开开发菜单。这两个参数加在开发客户端 Deep Link 的查询串中，会修改并保存菜单设置。

如果测试的是应用自己的深层路由（比如 `myscheme://orders/42`），URL 应按正式版的 deep link 写法构造，并且要先在开发构建里打开项目。当前不能用应用 Deep Link 冷启动开发构建；`expo-development-client` 是保留路径，勿把它写进业务路径。

## 为更新链接生成二维码

Expo 提供二维码 endpoint，返回可由开发构建扫描的 SVG。提供开发构建 scheme 与 URL 编码后的 update manifest URL：

```text
https://qr.expo.dev/development-client?appScheme=exp%2Bmy-app&url=https%3A%2F%2Fu.expo.dev%2F<project-id>%3Fchannel-name%3Dmain
```

### PR 预览

一种团队工作流是在每次 PR 更新时触发 EAS Update，再附上二维码，让具备兼容 Development Build 的成员直接检查界面。Expo 页面链接到 GitHub Actions 示例，也允许把它改作其它 CI 平台的模板。

## 给开发者菜单添加自定义入口

`expo-dev-menu` 的 `registerDevMenuItems` 可以注册调试按钮，例如打开本项目的诊断页：

```tsx
import { registerDevMenuItems } from 'expo-dev-menu';

registerDevMenuItems([
  {
    name: '打开调试信息',
    callback: () => console.log('打开调试信息'),
  },
]);
```

后续再次调用 `registerDevMenuItems` 会覆盖此前登记的菜单项，不会自动追加。

## 在启动器中浏览 EAS Updates

Development Build 可以扩展一个 EAS Update 区域，用于查看和打开已发布的 JS / asset 更新。SDK 56 按 Expo CLI 安装 `expo-dev-client` 与 `expo-updates`：

| 包管理器 | 命令 |
| --- | --- |
| npm / npx | `npx expo install expo-dev-client expo-updates` |
| Yarn | `yarn expo install expo-dev-client expo-updates` |
| pnpm | `pnpm expo install expo-dev-client expo-updates` |
| Bun | `bun expo install expo-dev-client expo-updates` |

如果项目还没启用 EAS Update，先完成官方的 EAS Updates 项目配置；之后启动器的 Extensions 面板就能显示并加载更新。

## 为原生 / JS 代码建立兼容边界：`runtimeVersion`

每个原生构建都固定包含当时的 native code 和配置。OTA 更新只能加载与其 `runtimeVersion` 相同的 build，因此要在 Expo 配置中定义 `runtimeVersion`，保证 JS bundle 和原生 API 契约匹配。

## 关键名词

- **EAS Update**：给已安装 app 发布 JS 与静态资源的 OTA 更新服务。
- **Channel**：把某类 EAS Update 路由给匹配构建的发布通道。
- **Manifest URL**：描述一份 Expo 更新及其资源的地址，启动器可以用它加载更新。
- **Deep Link**：使用 URL scheme 直接定位应用或更新的入口。
- **`runtimeVersion`**：原生 app binary 与 OTA JavaScript bundle 之间的兼容标识。
- **PR Preview**：针对一个代码变更 / Pull Request 提供的预览更新和二维码。
