## 发布之后要观察什么

应用上架或发给 Beta 用户后，可以观察用户实际使用的版本、功能行为、错误、性能和自动化测试稳定度。不同服务关注点不同。

| 工具 | 主要用途 | Expo 文档摘要 |
| --- | --- | --- |
| EAS Insights | 项目整体趋势 | App usage、EAS Workflows 运行情况、Maestro E2E 测试通过 / flaky / 失败趋势。App usage 由 EAS Update 请求与 `expo-insights` 聚合。 |
| EAS Observe | 生产性能 | 冷启动耗时、首帧 / 可交互时间、渲染表现及真实网络 / 设备条件下的体验；可记录自定义事件。 |
| LogRocket | 用户会话回放 | 录制用户 session 和问题线索，可按 EAS Update ID 过滤，也能在 EAS Dashboard 打开 LogRocket 数据。 |
| Sentry | 崩溃与异常 | 捕获生产 JS 异常和崩溃，记录 stack trace、设备、版本，也能补充路由和用户 ID 等上下文。 |
| BugSnag | 稳定性监控 | 汇总错误和稳定性事件，帮助复现和定位跨平台问题。 |
| PostHog | 产品分析 / Session Replay | 分析用户行为、回放会话、功能开关与错误；EAS CLI 可协助项目配置并按 EAS Update release tagging 事件。 |

## 关键名词

- **Real user monitoring**：从真实用户安装 / 使用过程中采集性能和错误数据，而非仅在开发模拟器测量。
- **Cold launch**：进程未运行时从头启动 app 的耗时。
- **Time to interactive**：界面可响应用户输入所需时间。
- **Flaky test**：同一自动化测试不稳定，时而通过、时而失败。
- **Release tagging**：在分析事件上标记 app / EAS Update 版本，方便对比发布前后变化。
