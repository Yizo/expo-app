## Expo Go 和 Development Build 有什么区别

Expo Go 是预先编译好固定原生库的测试 app。开发服务器实时提供 JS / TS bundle，Expo Go 用其中已有的原生 API 渲染界面。

Development Build 则是你自己的原生 app binary；它可以包含项目选择的原生依赖和 app 配置。它是完整产品开发使用的环境，也能在开发阶段快速重载 JS。

## 为什么不能只用 Expo Go 做所有事情

### 使用 Expo Go 未预装的原生库

执行 `npx expo install some-native-library` 会把 JS 和原生代码放进项目 `node_modules`，但只更新 JS bundle 并不会改变已经安装在手机上的 Expo Go。若该库的原生代码不在 Expo Go binary 中，JS 调用时就会找不到对应 native module 并报错。

例如，Expo Go 自带 `react-native-webview` 的原生实现；另一个未内置的原生库无法通过 Fast Refresh 临时添加进 Expo Go。选择 Development Build 后，库的原生实现会编进你自己的 app。

### 检查原生品牌与资源

App 名称、桌面图标和原生启动画面都随原生 binary 固定。使用 Expo Go 可以查看应用页面，但无法在通用容器里完整验收你 app 自己的图标和启动行为。Expo Go 的启动画面模拟只是用 app icon 代替，不能验收 `SplashScreen.setOptions` 等原生启动画面动画。

### 测试远程推送

应用内本地通知可以在 Expo Go 中试验；远程推送通知需要与你的 app 对应的推送凭证和原生配置，因此应在自己的 Development Build 中测试，确保与正式构建行为一致。

### 配置 App Links / Universal Links

Android App Links 与 iOS Universal Links 需要 app binary 声明它与网站之间的双向关联。Expo Go 的原生二进制无法为每一个 Expo 项目动态加入这种关联配置，所以这类 deep link 应使用自己的开发构建验证。

### 打开旧 SDK 项目

每个 Expo Go 版本只支持一个 Expo SDK。项目 SDK 与 Expo Go SDK 应匹配；在 Android 设备 / 模拟器和 iOS Simulator 可安装相应版本，或将项目升级到受支持的 SDK。真实 iOS 设备的安装规则不同，按官方 Expo Go 版本排查指南处理。

## 关键名词

- **Native app / 原生 app**：安装在设备上的 Android / iOS binary，包含原生模块和入口配置。
- **JavaScript bundle**：开发阶段由 Metro 从本机实时提供、或生产阶段随 app 发布的 JS 代码包。
- **Native module**：JS 调用的平台能力接口；代码必须先存在于设备当前运行的原生 app 中。
- **Remote push / 远程推送**：由服务器经 Apple / Google 推送服务送达设备的通知。
- **App Links / Universal Links**：Android / iOS 将网站 URL 映射到已安装 app 的系统级链接机制。
- **SDK 版本匹配**：运行项目的 Expo Go binary 与项目 Expo SDK 需要兼容，否则可能缺少该 SDK 需要的原生 API。
