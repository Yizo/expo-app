## 按数据类型选择

移动应用的数据保存位置应根据数据形状、隐私和容量选择。不同库的职责不一样，下面是 Expo 文档推荐的基本方向：

| 需求 | 方案 | 适合保存什么 | 特性 |
| --- | --- | --- | --- |
| 少量敏感键值 | `expo-secure-store` | 登录 token、密钥或少量凭证 | Android / iOS 使用系统安全存储保护数据；每个 Expo 项目相互隔离。适合小值，不适合大型文档或大量业务记录。 |
| 文件和二进制内容 | `expo-file-system` | 下载文件、上传文件、照片或用户导入文件 | 提供本机文件系统读写，也能下载 / 上传网络资源。Expo Go 中每个项目有独立文件系统，但可以通过项目间共享功能保存或分享本地文件。 |
| 结构化、可查询数据 | `expo-sqlite` | 需要多表关系、筛选、排序或持久化记录的数据 | SQLite 数据库跨应用重启保留，支持建表、插入、查询、Prepared Statements。 |
| 小量非敏感键值 | Async Storage | 用户偏好、简单 app 状态 | 异步、持久，但不加密；不应保存需要保密的数据。 |

## SecureStore：加密的小型键值

`expo-secure-store` 在设备本地加密保存键和值，适合少量 token 或密钥，不是远端账户数据库的替代品。v56 文档提醒，大型值可能被平台拒绝；旧 iOS 系统曾对约 2048 字节以上的值有限制。不要把不可恢复的重要数据仅存于 SecureStore。

Android 卸载应用时通常清除数据；iOS Keychain 可能在同 Bundle ID 重新安装后保留条目，但 Expo 明确建议不要依赖这种实现细节。启用生物识别保护时，如果用户更改指纹 / 面容设置，原值可能变得不可访问；Expo Go 中也有 `requireAuthentication` 的功能限制。

## FileSystem：文件的读写与传输

`expo-file-system` 面向文件而非表格数据。它可从网络 URL 上传 / 下载文件，也能管理 app 沙盒内的本地路径。Expo Go 会隔离不同项目的目录；如果需要项目间文件交接，应走文档提供的共享路径 / 文件分享能力。

## SQLite：持久化数据库

`expo-sqlite` 是本地 SQLite 数据库，可使用类似 WebSQL 的异步 API。数据库在应用重启后依然保留，适合多个实体、查询条件、离线记录和事务等场景。

页面建议先查看 SQLite API 参考与示例，了解导入现有数据库、打开数据库、创建表、插入、查询、迭代结果和 Prepared Statements。Prepared Statement 可以重复执行并自动处理输入参数转义，适合含用户输入的 SQL 查询。

## Async Storage：未加密的键值

Async Storage 是 React Native 生态的异步持久键值存储，适合偏好设置、小量 app 状态等不需要加密的内容。它不适合保存 token 或密码，因为值以未加密形式保存。

如需其它数据库 / 缓存方案，官方建议到 React Native Directory 搜索并核实平台支持、维护状态与 Expo Development Build 兼容性。

## 关键名词

- **键值存储**：用字符串 key 读写对应 value，适合单个小数据项，而不是复杂关系查询。
- **加密存储**：数据通过 Android Keystore / iOS Keychain 一类系统能力保护；库负责加解密，但仍应遵守容量和生命周期限制。
- **SQLite**：嵌入应用本机文件中的关系数据库；不需要单独运行一个数据库服务器。
- **Prepared Statement（预编译语句）**：带参数占位的 SQL 查询，执行时再绑定输入。使用它可避免把用户输入拼接成 SQL 文本。
- **持久化**：应用重启后数据仍然存在。
- **Expo Go 项目隔离**：一个 Expo Go 客户端可以打开多个 JS 项目，但每个项目的本地文件 / SecureStore 空间彼此独立。
