## 为什么需要平台分支

iOS / Android 可用 `react-native-view-shot` 从 native View 捕获画面，但浏览器 DOM 和 native View 并不是同一渲染树，原生截图模块不能直接截 Web 页面。教程对同一个保存按钮按平台分开实现：手机拍摄 View 并存入媒体库，Web 则把 DOM 节点转成 JPEG 并下载。

## Web 截图库

示范安装命令有多个包管理器形式：

```sh
npm install dom-to-image
yarn add dom-to-image
pnpm add dom-to-image
bun add dom-to-image
```

安装后重启 Expo CLI 并按 `W` 打开 Web。教程明确说这个库只是示例，正式产品应选符合平台、质量和无障碍要求的方案。

## 保存逻辑按平台分开

```tsx
async function saveArtwork() {
  if (Platform.OS !== 'web') {
    const localUri = await captureRef(imageRef, {
      height: 440,
      quality: 1,
    });
    await MediaLibrary.saveToLibraryAsync(localUri);
    return;
  }

  const dataUrl = await domtoimage.toJpeg(imageRef.current, {
    quality: 0.95,
    width: 320,
    height: 440,
  });

  const link = document.createElement('a');
  link.download = 'sticker-smash.jpeg';
  link.href = dataUrl;
  link.click();
}
```

`Platform.OS` 是运行时平台标记；`dataUrl` 是浏览器中可下载的图像编码。这里桌面浏览器用 DOM-to-image，移动端继续调用 native view-shot / Expo Media Library。浏览器实现中直接使用 `document`，它不属于 iOS / Android 原生组件环境。

## 给缺少类型定义的 JS 库补声明

如果 TypeScript 报 `dom-to-image` 没有类型声明，可在项目根目录添加 `types.d.ts`：

```ts
declare module 'dom-to-image';
```

这只让 TypeScript 接受模块导入，并不会凭空提供各函数的静态类型。

## 关键名词

- **DOM**：Web 浏览器实际渲染的 HTML 节点树。
- **Native View**：Android / iOS 的平台视图对象；它不是 HTML 节点。
- **`Platform.OS`**：React Native 用来选择不同平台逻辑的内置平台标识。
- **Data URL**：把图片数据编码在 URL 字符串中，浏览器可将其作为下载目标。
- **Declaration file**：`.d.ts` 文件，为无类型 JS 库声明 TS 模块接口。
