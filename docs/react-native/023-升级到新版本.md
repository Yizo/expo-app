# 023 升级到新版本（Upgrading to New Versions）

**翻页：** [上一页：022 Release Levels](022-ReleaseLevels.md) · [目录](README.md) · [下一页：024 Style](024-Style.md)

**官方页面：** [Upgrading to New Versions · React Native](https://reactnative.dev/docs/upgrading)  
**源页代码覆盖：** RN/React 版本安装命令（npm/Yarn 两种）、项目升级文件比对流程、缓存排查建议；并说明 Expo 项目按 SDK 一次升级一个版本。

## 升级为什么涉及多层文件

原生 RN 应用包含 Android 工程、iOS 工程和 JavaScript 工程。升级 React Native 时不仅要改 `package.json`，也可能要改 Gradle、CocoaPods、Manifest、Xcode Build Settings 和原生入口。因此官方提供 Upgrade Helper，对比任意 RN 版本间模板文件的变化并解释原因。

## Expo 工程

本页提示，Expo 项目升级涉及与 Expo SDK 配套的 `expo`、`react-native` 和 `react` 版本。官方建议逐个 SDK 版本升级，便于定位变化。本页链接了 Expo SDK Upgrade Walkthrough；实际命令和 SDK/RN 兼容表需跟随 Expo 指南，不要只看 RN 核心版本的 latest。

## 裸 RN 工程升级流程

1. 在 Upgrade Helper 选择当前版本和目标版本，查看所有变更文件。大版本升级时先读额外的迁移说明。
2. 根据 `package.json` 的差异更新包版本。RN 页面用以下占位形式演示，实际值取自所选 diff：

```sh
npm install react-native@<目标 RN 版本>
npm install react@<匹配 React 版本>
# 或者
yarn add react-native@<目标 RN 版本>
yarn add react@<匹配 React 版本>
```

3. 将其他模板文件变更逐项应用到现有工程，不要把旧配置整份替换掉而丢失应用自己的改动。
4. 安装原生依赖，重新构建 Android/iOS 工程并处理剩余升级错误。

## 更新后仍显示旧版本

如果依赖已更新、工程文件也同步，但设备仍使用旧代码，官方指出这通常与缓存相关。先确认实际启动的工程、安装包和 Metro bundle；之后再按 RN 当前版本清缓存指南处理。RN 页面提到 `react-native-clean-project` 作为清缓存工具，可以作为排查选项，不代表所有版本都应无条件运行。
