## 选择和安装包管理器

JavaScript 社区里 “library（库）” 和 “package（包）” 常交替使用。RN 库通常从 npm registry 获取，常用 npm CLI 或 Yarn Classic 安装；示例以 npm 为主，Yarn 同样适用。RN 核心内置组件/API 以外，可以寻找社区库补充能力。

## 安装原生依赖

以 `react-native-webview` 为例，安装命令会把依赖加进工程的 package 清单。库如果带 Android/iOS 原生代码，光刷新 JS bundle 不够：原生依赖要链接并重新构建 App。

```sh
npm install react-native-webview
# 或
yarn add react-native-webview
```

iOS 通常通过 CocoaPods 管理原生依赖。在 iOS 目录运行 `pod install`，或从工程根目录用快捷工具触发它；随后重新构建 iOS binary：

```sh
npx pod-install
npm run ios
# 或
yarn ios
```

Android 由 Gradle 管理依赖；有原生代码的包安装后同样要重新构建：

```sh
npm run android
# 或
yarn android
```

只有 JavaScript 文件的库一般不需原生重建，但是否存在原生部分要看库文档。

## 找到适配 RN 的库

先查 React Native Directory，它可检索库并筛选 iOS、Android、Web、Windows 等平台支持。社区库由维护者各自管理，支持的平台和更新节奏不一。Expo 组织维护的库很多以 TypeScript 编写，并尽可能支持 iOS、Android 和 `react-native-web`。

如果 Directory 没有目标库，可以再查 npm registry；但 npm 上的所有包都不意味着支持 RN。判断库是否兼容时至少检查：

1. **运行环境：** 是否面向 RN，而不是只面向 Web DOM（如 `react-dom`）或 Node 文件系统。
2. **平台：** 是否支持应用要发布的平台。
3. **版本：** 是否适配当前 RN 版本。旧 RN 项目可能要锁定兼容的库版本。
4. **原生要求：** 是否需要 CocoaPods/Gradle、额外系统权限或手动配置。

纯 JS、只用标准语言特性的库通常更容易跨环境；Web UI 包和 Node 文件系统工具不能因为写成 JS 就直接放进 RN。若不兼容，可移除该依赖，换用 RN 专用实现：

```sh
npm uninstall some-web-only-package
npm install @react-native-community/netinfo@^2.0.0
```

第二行示意安装某个指定版本范围；实际版本按当前库的兼容说明选择。
