## 什么时候用这条路线

如果已经有一个由 Kotlin/Java 或 Swift/Objective-C 写成的手机应用，可以把 React Native 加进去，逐步新增一个页面或用户流程；不一定要一次性重写整款应用。此指南是把 JS 视图嵌入现有原生工程，需要同时理解 RN 和对应平台的 Activity、ViewController、Gradle 或 CocoaPods。全新项目通常先考虑上一页介绍的框架路线。

官方指南建议使用对应 RN 版本的 Community Template 作为原生配置参照。本页很长，安卓和 iOS 示例分别覆盖多个文件；版本更新时应按当前模板对比 Gradle 插件、Podfile、架构初始化和构建脚本。

## 项目结构与 JS 依赖

建立新的集成根目录，把原生项目放进 `android/` 或 `ios/`。根目录需要 RN template 对应的 `package.json`、JS/TS 入口和 Metro 配置；安装依赖后会生成 `node_modules/`，应由 `.gitignore` 排除。官方页演示从与 RN 0.87 对应的 React Native Community Template 下载 `package.json`，再用 npm 或 Yarn 安装依赖：

```sh
curl -O https://raw.githubusercontent.com/react-native-community/template/refs/heads/0.87-stable/template/package.json
npm install
# 或
yarn install
```

`index.js` 是 JS bundle 注册根组件的入口。原生宿主会按注册名启动它。

```js
import { AppRegistry } from 'react-native';
import App from './App';

AppRegistry.registerComponent('EmbeddedScreen', () => App);
```

## RN 侧页面组件

页面示例用 RN 安全区域、状态栏、滚动容器、View/Text 和系统配色显示一屏 UI。源页还示范从模板导入调试提示组件；这些组件来自 RN 私有示例目录，不适合作为应用长期依赖。下例只用核心公共组件，表达相同的根组件结构：

```tsx
import { useColorScheme } from 'react-native';
import { SafeAreaView, ScrollView, StatusBar, Text, View } from 'react-native';

export default function EmbeddedApp() {
  const dark = useColorScheme() === 'dark';
  const backgroundColor = dark ? '#171717' : '#f7f7f7';

  return (
    <SafeAreaView style={{ flex: 1, backgroundColor }}>
      <StatusBar barStyle={dark ? 'light-content' : 'dark-content'} />
      <ScrollView contentInsetAdjustmentBehavior="automatic">
        <View style={{ padding: 24 }}>
          <Text style={{ fontSize: 24, fontWeight: '600' }}>混合应用中的 RN 页面</Text>
          <Text>这里的内容仍由 React 组件树绘制。</Text>
        </View>
      </ScrollView>
    </SafeAreaView>
  );
}
```

## Android：Gradle、应用入口与 Activity

### Gradle 和 Manifest

**RNGP** 是 React Native Gradle Plugin。它负责将 RN 依赖和构建配置接进 Android 工程；设置阶段配置 plugin 和 autolinking，根级 `build.gradle` 引入插件，App 模块应用插件并声明 React Android/Hermes 实现。新版模板还在 `gradle.properties` 中控制应用 ABI、New Architecture 和 Hermes。ABI 是 CPU 指令集目标，Hermes 是 RN 的 JavaScript 引擎，New Architecture 是 RN 当前原生渲染/模块架构。

```gradle
// settings.gradle：装载并初始化 RN Gradle settings plugin
pluginManagement { includeBuild('../node_modules/@react-native/gradle-plugin') }
plugins { id('com.facebook.react.settings') }
extensions.configure(com.facebook.react.ReactSettingsExtension) { cfg ->
  cfg.autolinkLibrariesFromCommand()
}
includeBuild('../node_modules/@react-native/gradle-plugin')
```

App 模块的要点可概括为：应用 RN Gradle 插件、声明 `react-android` 与 Hermes 依赖，并让 RNGP 执行 autolinking。请从目标版本模板复制完整 DSL；Groovy 和 Kotlin DSL 文件语法不同。

```gradle
apply plugin: 'com.android.application'
apply plugin: 'com.facebook.react'

dependencies {
  implementation('com.facebook.react:react-android')
  implementation('com.facebook.react:hermes-android')
}

react { autolinkLibrariesWithApp() }
```

页面还要求在 `gradle.properties` 中设置目标 CPU 架构列表，并决定是否启用新架构和 Hermes。开关应与目标工程及依赖相符；下面列出源页对应的属性类别：

```properties
reactNativeArchitectures=arm64-v8a,armeabi-v7a,x86_64
newArchEnabled=true
hermesEnabled=true
```

AndroidManifest 需要网络权限，让调试应用可以读取开发机上的 Metro bundle。若本地 Metro 使用 HTTP 明文流量，只在 debug manifest 打开明文流量选项；不要把调试例外放进 release 配置。

```xml
<!-- 整个工程保留一个 application；示例中的明文 HTTP 设置只进 debug manifest -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
  <uses-permission android:name="android.permission.INTERNET" />
  <application android:name=".MainApplication" android:usesCleartextTraffic="true">
    <!-- Activity 在这里注册 -->
  </application>
</manifest>
```

### Android 原生启动 RN

自定义 `Application` 要实现 `ReactApplication` 并创建 React Native host。Java/Kotlin 模板都做同一批工作：从 `PackageList` 收集自动链接包、把 JS 入口指向 `index`、仅在 Debug 开开发支持、读取 Hermes/New Architecture 构建开关；在 `onCreate` 初始化 SoLoader，并在启用新架构时加载对应入口。新版模板也提供 `ReactHost`。

```kotlin
class MainApplication : Application(), ReactApplication {
  override val reactNativeHost = object : DefaultReactNativeHost(this) {
    override fun getPackages() = PackageList(this).packages
    override fun getJSMainModuleName() = "index"
    override fun getUseDeveloperSupport() = BuildConfig.DEBUG
    override val isNewArchEnabled = BuildConfig.IS_NEW_ARCHITECTURE_ENABLED
    override val isHermesEnabled = BuildConfig.IS_HERMES_ENABLED
  }

  override fun onCreate() {
    super.onCreate()
    SoLoader.init(this, OpenSourceMergedSoMapping)
    if (BuildConfig.IS_NEW_ARCHITECTURE_ENABLED) load()
  }
}
```

原生 `Activity` 通过 `ReactActivity` 托管 RN 页面，并返回与 `AppRegistry.registerComponent` 一致的组件名；Manifest 要声明该 Activity，通常选无 ActionBar 主题，避免 RN 页面上又出现原生 ActionBar。页面分别给 Java 和 Kotlin 写法，职责相同。

```kotlin
class EmbeddedReactActivity : ReactActivity() {
  override fun getMainComponentName() = "EmbeddedScreen"
  override fun createReactActivityDelegate(): ReactActivityDelegate =
    DefaultReactActivityDelegate(this, mainComponentName, fabricEnabled)
}
```

Java 模板做同一件事：从 `ReactActivity` 继承、返回注册名，并通过默认 delegate 接入 Fabric/new architecture 的开关。

```java
public final class EmbeddedReactActivity extends ReactActivity {
  @Override
  protected String getMainComponentName() {
    return "EmbeddedScreen";
  }

  @Override
  protected ReactActivityDelegate createReactActivityDelegate() {
    return new DefaultReactActivityDelegate(
        this, getMainComponentName(), DefaultNewArchitectureEntryPoint.getFabricEnabled());
  }
}
```

同样，Java 版 `Application` 会覆写 `getReactNativeHost()`，并从 `PackageList` 返回自动链接包、指定 JS 入口、读取 Debug/Hermes/New Architecture 标记；`onCreate()` 初始化 SoLoader 并按开关加载新架构。Kotlin 版在上一代码块里逐项展示了这些职责。

```java
public final class MainApplication extends Application implements ReactApplication {
  private final ReactNativeHost host = new DefaultReactNativeHost(this) {
    @Override protected List<ReactPackage> getPackages() {
      return new PackageList(this).getPackages();
    }
    @Override protected String getJSMainModuleName() { return "index"; }
    @Override public boolean getUseDeveloperSupport() { return BuildConfig.DEBUG; }
    @Override protected boolean isNewArchEnabled() {
      return BuildConfig.IS_NEW_ARCHITECTURE_ENABLED;
    }
    @Override protected Boolean isHermesEnabled() { return BuildConfig.IS_HERMES_ENABLED; }
  };

  @Override public ReactNativeHost getReactNativeHost() { return host; }

  @Override public void onCreate() {
    super.onCreate();
    SoLoader.init(this, OpenSourceMergedSoMapping);
    if (BuildConfig.IS_NEW_ARCHITECTURE_ENABLED) {
      DefaultNewArchitectureEntryPoint.load();
    }
  }
}
```

### Android Metro 与发布构建

`metro.config.js` 读取 RN 默认 Metro 配置；执行 npm/Yarn start 启动开发服务器，App 通过本机网络载入 JS，因而可以 Fast Refresh。Release 可以让 Android Studio 或 Gradle Plugin 把 JS bundle 放进 APK/AAB；命令行模板示例分别产出 APK 与 App Bundle：

```js
const { getDefaultConfig } = require('@react-native/metro-config');
module.exports = getDefaultConfig(__dirname);
```

```sh
npm start
cd android
./gradlew :app:assembleRelease  # APK
./gradlew :app:bundleRelease    # AAB
```

## iOS：CocoaPods、RN 工厂与视图控制器

### CocoaPods 依赖

iOS 工程放在 `ios/`；安装 Node 依赖后，通过 CocoaPods 将 RN 原生代码集成到 Xcode 工程。Gemfile 声明 Ruby gems，Podfile 声明 iOS Pods。官方页示范从 RN 0.87 Community Template 获取这两个文件，再 `bundle install` 和 `bundle exec pod install`。它特别提示：基于 Xcode 16 的工程可能需要锁定较新的 CocoaPods 与 xcodeproj gem；请按本机 Xcode 和 RN 模板查看确切版本。

```sh
curl -O https://raw.githubusercontent.com/react-native-community/template/refs/heads/0.87-stable/template/Gemfile
curl -O https://raw.githubusercontent.com/react-native-community/template/refs/heads/0.87-stable/template/ios/Podfile
brew install cocoapods
bundle install
bundle exec pod install
```

官方页还用一个 Gemfile diff 示范 Xcode 16 项目的 gem 版本约束调整：检查 CocoaPods 与 `xcodeproj` 的版本要求；该版本对只是 RN 0.87 模板示例，不能套到其他 Xcode/RN 组合。

```ruby
gem 'cocoapods', '1.16.2'
gem 'activesupport', '>= 6.1.7.5', '!= 7.1.0'
gem 'xcodeproj', '1.27.0'
```

### iOS 初始化 RN

RN 页面展示 Objective-C 与 Swift 的写法。当前示例通过 `RCTReactNativeFactory` 初始化 RN runtime；delegate 提供 Debug 时 Metro 上的 `index` bundle URL，Release 时读取应用内 `main.jsbundle`。接着 factory 创建名为 `EmbeddedScreen` 的根视图，放到 `UIViewController.view` 中。

```swift
import UIKit
import React
import React_RCTAppDelegate
import ReactAppDependencyProvider

final class EmbeddedReactViewController: UIViewController {
  private var factory: RCTReactNativeFactory?
  private var factoryDelegate: RCTReactNativeFactoryDelegate?

  override func viewDidLoad() {
    super.viewDidLoad()
    let delegate = ReactNativeDelegate()
    delegate.dependencyProvider = RCTAppDependencyProvider()
    factoryDelegate = delegate
    let rnFactory = RCTReactNativeFactory(delegate: delegate)
    factory = rnFactory
    view = rnFactory.rootViewFactory.view(withModuleName: "EmbeddedScreen")
  }
}
```

Objective-C 模板用相同的工厂对象和 bundle URL delegate。下面保留最关键的对象关系：Debug bundle 由 Metro 提供，Release bundle 来自 App 包内资源。

```objc
@interface EmbeddedFactoryDelegate : RCTDefaultReactNativeFactoryDelegate
@end

@implementation EmbeddedFactoryDelegate
- (NSURL *)bundleURL {
  #if DEBUG
  return [RCTBundleURLProvider.sharedSettings jsBundleURLForBundleRoot:@"index"];
  #else
  return [NSBundle.mainBundle URLForResource:@"main" withExtension:@"jsbundle"];
  #endif
}
@end

// 在 UIViewController 中初始化工厂并创建 RN 根视图
_factory = [[RCTReactNativeFactory alloc] initWithDelegate:delegate];
self.view = [_factory.rootViewFactory viewWithModuleName:@"EmbeddedScreen"];
```

原生首页可以通过 UIKit 按钮呈现这个 ViewController；官方代码给 Objective-C 与 Swift 两套按钮、事件回调和 Auto Layout 约束示例。关键动作是点击后创建或重用 RN 容器，再通过 `present` 显示。生产工程应按自身导航架构把它推入原生导航栈或作为子视图，不必照搬示例模态呈现。

原页中的 Swift 按钮回调用 `UIAction`，Objective-C 用 `addTarget:action:forControlEvents:`；两者把点击事件交给宿主控制器的方法，再呈现 RN 控制器。约束都把按钮的边缘和中心锚点连到父视图，避免使用固定屏幕坐标。

```objc
UIButton *button = [UIButton new];
[button setTitle:@"打开 RN 页面" forState:UIControlStateNormal];
[button addTarget:self action:@selector(showReactScreen)
 forControlEvents:UIControlEventTouchUpInside];
[self.view addSubview:button];
button.translatesAutoresizingMaskIntoConstraints = NO;
// 使用 NSLayoutConstraint 将按钮四边/中心约束到父视图
```

页面还要求检查 Xcode 的 User Script Sandboxing 配置，并在 Info.plist 设置 `UIViewControllerBasedStatusBarAppearance`，以便 RN 的 Hermes Debug/Release 脚本与状态栏管理正常工作。两项都是特定工程配置，按当前模板确认后再改。

### iOS Metro 与 Release bundle

`metro.config.js` 使用默认 Metro 配置；页面要求根目录有空对象 `.watchmanconfig`。运行 Metro 后用 Xcode 构建设备端应用，调试模式会连开发服务器。Release 需要在 Build Phases 添加 RN bundle script，并放在 `[CP] Embed Pods Frameworks` 脚本之前，让 JS 和图片随应用打包：

```json
{}
```

页面要求 `metro.config.js` 从 RN 的 Metro 配置包取得默认值；概念上是 `getDefaultConfig(__dirname)`。Android/iOS 原生模板都能看到类似配置。开发脚本分别可用 `npm start` 或 `yarn start`。

```sh
echo '{}' > .watchmanconfig
npm start
# 或 yarn start
```

Xcode Run Script 的行为可概括为：载入 RN 的环境变量脚本，再执行 `react-native-xcode.sh` bundle 脚本；确保脚本以错误即停方式运行，并放在 CocoaPods framework embed 阶段之前。完整模板片段应以对应版本的 Community Template 为准。

```sh
set -e
WITH_ENVIRONMENT="$REACT_NATIVE_PATH/scripts/xcode/with-environment.sh"
REACT_NATIVE_XCODE="$REACT_NATIVE_PATH/scripts/react-native-xcode.sh"
/bin/sh -c "$WITH_ENVIRONMENT $REACT_NATIVE_XCODE"
```

## 把原生数据作为启动 props 传入 JS

原生宿主可在创建 RN root view 时传 `initialProperties`（Android Fragment 指南使用 launch options）。`App` 接收 props 后便能按传入值显示或请求数据。官方示例用 user ID 和 token 演示；真实 token 是敏感凭证，不应硬编码、打印或写进公开示例。

```tsx
type NativeLaunchProps = { accountId: string };

export default function EmbeddedApp({ accountId }: NativeLaunchProps) {
  return <Text>当前账号：{accountId}</Text>;
}
```

```swift
let view = factory.rootViewFactory.view(
  withModuleName: "EmbeddedScreen",
  initialProperties: ["accountId": "demo-account"]
)
```

Objective-C 对应实现把同样的键值装进 `NSDictionary` 传给 root view factory：

```objc
NSDictionary *props = @{@"accountId": @"demo-account"};
UIView *root = [factory.rootViewFactory
    viewWithModuleName:@"EmbeddedScreen"
    initialProperties:props];
```

同理，Objective-C 可向 `initialProperties` 字典传键值，JS 组件的 props 名称要一致。为保持示例安全，这里用非敏感的 demo account 替代页面中的令牌示例。
