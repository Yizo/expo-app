# 007 故障排除（Troubleshooting）

**官方页面：** [Troubleshooting · React Native](https://reactnative.dev/docs/troubleshooting)
**源页代码覆盖：** 端口查询/终止/改端口、npm 权限、Podfile、WebSocket 导入顺序、ADB 重启、inotify 限额、gradlew 执行权限等命令与配置。
**说明：** 官方页汇集多个环境故障。下面按故障原因释义，并重写必要命令。该页有旧式 CLI、CocoaPods 和原生依赖说明；新项目或不同架构应先核对当前官方版本文档。

## Metro 端口 8081 已被占用

Metro 是 RN 的 JavaScript 打包/开发服务器，默认监听 8081。若该端口已经被其他进程占用，可以确认进程后停止它，或为 Metro 换端口。停止进程前先确认 PID 对应的确是可以关闭的进程；不必一开始就用强制终止。

```sh
# 查看是谁在监听开发服务器端口
lsof -nP -iTCP:8081 -sTCP:LISTEN

# 确认后，优先正常结束进程；将 PID 替换成查到的进程编号
kill <PID>

# 给开发服务器选择一个备用端口
npm start -- --port 8090
# 或者
yarn start --port 8090
```

改端口后，原生调试客户端也要能从这个端口读取 bundle；完全原生的 iOS 工程可能还需检查 Xcode 工程里开发服务器地址的端口配置。

## npm 权限错误 `EACCES`

这通常是 npm 缓存或全局安装目录的所有权不属于当前用户。先检查权限与 Node/npm 安装方式；避免不加判断地对整个 home 或系统目录执行递归 `chown`，否则可能改变大量文件的属主。可按当前 Node 安装方式修复对应目录权限，或者用 Node 版本管理器管理安装。

## 原生依赖没链接或 Xcode 找不到符号

如果手动集成 RN，iOS 工程要把用到的 React Native 原生模块包含并链接进应用。旧式 CocoaPods 配置需要针对使用到的能力（例如 Text、Image、网络和 WebSocket）声明相应 subspec，并运行 `pod install`。完成后继续通过 CocoaPods 生成的 `.xcworkspace` 打开工程，而不是单独打开 `.xcodeproj`。

概念示意（依赖名称和适用方式请以该 RN 版本及架构的集成指南为准）：

```ruby
pod 'React', :path => '../node_modules/react-native', :subspecs => [
  'RCTText',
  'RCTImage',
  'RCTNetwork',
  'RCTWebSocket',
]
```

若 Xcode 报递归展开头文件路径过长，检查 `User Search Header Paths` 与 `Header Search Paths` 是否被手动改成过大的目录。CocoaPods 管理的工程应优先恢复默认搜索路径，避免从大型目录递归扫描。

## WebSocket 初始化顺序

RN 提供 WebSocket 全局能力的兼容层。页面提示，若依赖该全局能力的第三方包在 RN 环境初始化前载入，可能发生没有可用传输通道的问题。先加载 RN 应用入口，再加载需要 WebSocket 的库。下面是示意，具体 Firebase 包入口需按所用 SDK 版本调整：

```ts
import 'react-native';
import messagingClient from 'some-messaging-package';
```

## Android 命令或模拟器故障

- 安装调试 APK 时若 ADB 抛出 `ShellCommandUnresponsiveException`，重启 ADB server 再试：

  ```sh
  adb kill-server
  adb start-server
  ```

- Linux 上 Watchman/inotify 监控目录数达到上限时会看到 `ENOSPC`。官方页给出提高 `fs.inotify.max_user_watches` 的方法；这是系统级配置，修改前先确认额度问题，并查当前 Linux 发行版文档。
- macOS 报 `spawnSync ./gradlew EACCES` 时，可能是 Gradle wrapper 没有可执行权限。只对项目里的 wrapper 文件设置执行位：

  ```sh
  chmod u+x android/gradlew
  ```

  原文示例采用 `sudo chmod`；普通项目通常先尝试当前用户权限即可，不要无必要地扩大权限。

## 编译时库缺失

检查原生依赖确实安装、Pods/Gradle 依赖已同步、应用链接了要求的库，并且使用正确的工作区/构建目标。手动链接步骤、旧架构原生库名可能随 React Native 架构变化；本页链接的现代安装与原生模块指南应优先参考。

## 排查顺序

1. 先读第一条真正报错和失败目标，分清 Metro、Node/npm、Android 构建、Xcode/PODS 或设备连接问题。
2. 查看版本与工程状态；RN 核心、Node、JDK、Gradle、Android SDK、Xcode 和 Pods 需彼此兼容。
3. 按所属平台检查工具配置和依赖链接，再做最小可复现尝试。
4. 未列出的错误可从官方项目问题与文档入口继续搜索，但先确认问题对应的 RN 版本和架构。
