## Android/iOS 以外的生态

“树外平台”指不在 React Native 核心仓库内维护、但可将 RN 带到更多宿主系统或渲染环境的项目。官方页面列出合作方平台（macOS、Windows、visionOS、OpenHarmony）与社区项目（tvOS、React Native Web、使用 Skia 渲染的 Linux/macOS）。这些项目维护者与版本节奏不同，应直接查看对应项目的支持矩阵。

## 自己维护一个平台

页面指出，从头创建平台的过程仍缺少完整文档；New Architecture 与 Fabric 的目标之一是降低平台维护成本。Fabric 是 React Native 新架构的渲染器。普通应用开发者无需注册新平台，只有维护 RN 打包器/原生 renderer 集成的团队才会涉及。

旧版页面给出 Metro 平台后缀方式：打包时传一个平台名（示例名 `example`），Metro 就会查找 `.example.js` 实现。该能力从历史 RN 0.57 起就存在；新建自定义平台前应核对当前 Metro CLI 与架构文档。

```sh
npx react-native bundle --platform example
```

页面还展示 RNPM/Haste 时期的 package 元信息。这个注册形式是旧式配置，应按当前 CLI/Metro 版本文档确认能否使用；此处保留它作为官方页代码主题的释义示意，而非新项目推荐配置：

```json
{
  "rnpm": {
    "haste": {
      "providesModuleNodeModules": ["react-native-example"],
      "platforms": ["example"]
    }
  }
}
```

`platforms` 列出平台后缀，`providesModuleNodeModules` 声明参与 Haste 模块查找的包。Metro/Haste 的配置历史与当前默认 RN 模板有差异；实际采用前要找目标版本的官方/维护者说明。
