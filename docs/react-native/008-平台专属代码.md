## 共享代码与平台差异

跨平台应用应尽量共用逻辑和界面代码，但小部分外观、API 或平台行为可能需要分支。RN 文档介绍两种主要方式：运行时使用 `Platform` 模块选择行为，或用 `.ios`、`.android` 等文件名后缀让 Metro 解析对应文件。API 文档中标有平台徽标的 prop 通常不是所有平台都支持。

## `Platform.OS` 和 `Platform.select`

`Platform.OS` 可返回当前系统标识，例如 `ios` 或 `android`。只需一个值不同的简单情况，用条件表达式即可。`Platform.select` 接收一个候选对象，并按运行平台选择值；通常优先找具体平台键，其次考虑 `native`，最后用 `default`。

```tsx
import { Platform, StyleSheet, View } from 'react-native';

const panelStyles = StyleSheet.create({
  box: {
    height: Platform.OS === 'ios' ? 180 : 140,
    ...Platform.select({
      ios: { backgroundColor: '#f5d5d5' },
      android: { backgroundColor: '#d8efdc' },
      default: { backgroundColor: '#d8e7f7' },
    }),
  },
});

export function PlatformPanel() {
  return <View style={panelStyles.box} />;
}
```

`Platform.select` 不只能返回样式值，也可以返回平台组件或工厂函数。可在一个公共文件中选择 iOS 和 Android 实现，也可选择两个原生平台共用版本和 Web 的不同版本：

```tsx
import { Platform } from 'react-native';

const NativeWidget = Platform.select({
  ios: () => require('./WidgetIos').default,
  android: () => require('./WidgetAndroid').default,
  default: () => require('./WidgetFallback').default,
})();

export function WidgetSlot() {
  return <NativeWidget />;
}

const SharedOnPhones = Platform.select({
  native: () => require('./MobileWidget').default,
  default: () => require('./BrowserWidget').default,
})();
```

模块导入方案要留意静态分析和类型检查；也可以直接用平台扩展名文件，由打包器选择正确实现。示例只解释分支机制。

## 检测系统版本

Android 的 `Platform.Version` 表示 Android API 级别。iOS 的 `Platform.Version` 是系统版本字符串，可以解析主要版本号。按旧系统版本做条件判断时需要谨慎：现代系统版本范围、API 支持策略以及依赖兼容性可能变化，优先做能力检测或通过支持矩阵判断。

```tsx
import { Platform } from 'react-native';

if (Platform.OS === 'android' && Platform.Version === 35) {
  console.log('当前 Android API 级别为 35');
}

if (Platform.OS === 'ios') {
  const iosMajor = Number.parseInt(String(Platform.Version), 10);
  if (iosMajor <= 16) {
    console.log('需要处理旧版 iOS 的行为差异');
  }
}
```

## 用文件扩展名拆分实现

功能差异较大时，把实现放到独立文件中可让各平台代码保持简单。引用时不写后缀，Metro 会优先解析适用于当前目标的文件，例如 `MapCard.ios.tsx` 与 `MapCard.android.tsx`。Web 文件和 RN 文件需要共享逻辑时，可使用通用 `.js/.tsx` 与原生专用 `.native.js/.native.tsx`；Web bundler 应配置忽略原生实现，避免把不用的代码打进 Web 包。

```text
MapCard.ios.tsx       # iOS 原生专用实现
MapCard.android.tsx   # Android 原生专用实现
MapCard.native.tsx    # iOS 和 Android 共用实现
MapCard.tsx           # Web 或通用实现
```

```tsx
import MapCard from './MapCard';

export default function MapScreen() {
  return <MapCard />;
}
```

选择原则：只有少量值不同，使用 `Platform.OS` / `Platform.select`；页面或组件实现明显分叉，使用平台文件；逻辑完全共用时保留普通通用模块。
