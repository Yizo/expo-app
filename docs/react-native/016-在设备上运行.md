**源页代码覆盖：** Android USB 调试与 ADB 设备查询、`adb reverse`、npm/Yarn 启动与 Release 模式、Wi-Fi 开发服务器地址、Linux USB vendor/udev 配置；iOS 设备签名和 Xcode 构建/运行操作。

## 用真机测试的原因

模拟器适合开发，但发布前还要在真实设备上确认性能、权限、键盘、网络、尺寸等行为。Expo 项目可在开发服务器启动后通过 Expo Go 扫描二维码；无框架 RN 项目按平台原生开发工具连接设备。本文描述 RN 0.87 页面快照中的原生设备流程。

## Android：USB 调试和启动应用

先在 Android 设置中启用开发者选项，再打开 USB debugging。通常可在“关于手机”里的 Build number 连点七次开启开发者菜单。用 USB 接上电脑后，ADB（Android Debug Bridge）负责发现设备、安装 App、执行反向端口转发。

```sh
adb devices
```

状态列显示 `device` 才表示授权且在线；若显示 `unauthorized`，在手机弹窗允许调试。多个设备同时接入时用 `-s <设备序列号>` 明确指定目标，避免把命令发错设备。

```sh
npm run android
# 或
yarn android

# 通过 RN CLI 构建并在设备安装 release variant 的例子
yarn android --mode release
```

## 让真机连接本地 Metro

Metro 在开发机运行，Android 设备需要访问其 bundle。USB 连接时，官方推荐用 ADB reverse，把设备端的 8081 映射回开发机：

```sh
adb -s <设备序列号> reverse tcp:8081 tcp:8081
```

Android 5.0 及以后、启用 USB debugging 且通过 USB 连接时可用。完成后在开发菜单开启 Fast Refresh，保存 JS 变更即可快速更新。

没有 USB 线时，可先用 USB 安装应用，再通过 Wi-Fi 调试：手机与电脑连接同一网络，在 RN Dev Menu 的 Dev Settings 填入开发机 IP 和 Metro 端口（例如 `192.168.1.20:8081`），然后触发 Reload JS。Windows 可用 `ipconfig` 查 IP；macOS 从 Network 设置查看；Linux 用发行版提供的网络命令检查地址。

```powershell
ipconfig
```

## Linux 真机权限

Linux 可能需要 USB udev 规则，让当前开发用户能访问手机。页面示范先用 `lsusb` 找手机厂商 ID，再写入规则；实际 vendor ID 要换成自己的设备值，用户组和规则权限也应按本机安全策略确认。

```sh
lsusb
# 从输出取厂商 ID（例如前四位），再按发行版说明配置 udev
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="<厂商ID>", MODE="0660", GROUP="plugdev"' \
  | sudo tee /etc/udev/rules.d/51-android-usb.rules
```

把权限设置为“所有用户可写”（如 `0666`）会扩大访问范围；此学习示例使用仅用户组可写的 `0660`，并提示先确认目标组、重载 udev，再检查 `adb devices` 是否识别。

## Android 发布

生产发布流程与一般 Android 应用类似：需要按 Play Store 要求签名，产出 APK 或 AAB，并处理密钥、版本、商店配置。RN 页面链接到 Android 签名构建指南；开发调试用 USB 配置不等同于发布签名。

## iOS：设备信任、签名和运行

iOS 真机开发需要 Mac 与 Xcode。用 USB 将 iPhone/iPad 接到 Mac，打开 `ios` 下的 `.xcodeproj`，若使用 CocoaPods 则打开 `.xcworkspace`。首次使用的设备需在 Xcode Product > Destination 中注册。再在工程与 Tests target 的 Signing 配置中选择 Apple Developer Team，使用工具栏的 Run 或快捷键构建并安装应用。

真机连开发服务器时，手机和 Mac 需在同一可互访 Wi-Fi。打开 RN Dev Menu 并启用 Fast Refresh。若出现 `localhost:8081/debugger-proxy` 连接超时，检查网络隔离、构建时写入的开发机 IP 是否正确；公共 Wi-Fi 可能阻止设备互访，可使用个人热点或 USB 网络共享。

Android 与 iOS 的发布包都要走平台原生签名和商店发布流程。React Native 负责 JS 组件与原生工程集成，但不会替代 Android/iOS 的签名和审核要求。
