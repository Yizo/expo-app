## 架构术语对照

| 官方术语 | 中文解释 | 与 Web React 的联系 |
|---|---|---|
| **Dev Menu** | Development build 中的应用内开发菜单，可访问调试、重载等操作。 | 类似本地开发时的调试面板，不是最终用户页面。 |
| **Fabric Renderer** | React Native 的新渲染器，负责协调 React 与各平台 Host View 的实例和更新。 | ReactDOM 渲染到 DOM；Fabric 渲染到平台原生视图。 |
| **Host platform** | 嵌入 React Native 的操作系统或运行平台，如 Android、iOS、macOS、Windows。 | 相当于目标渲染宿主环境。 |
| **Host View Tree** | 平台原生视图构成的树；Android 由 `ViewGroup`、`TextView` 等组成。 | 类似 DOM Tree，但节点是原生控件，不是 HTML 元素。 |
| **JSI** | JavaScript Interface；让 JS 引擎与 C++ 接口互通，供 Fabric 等调用。 | 不等于浏览器 API，也不是 UI 组件；它是原生互操作边界。 |
| **JNI** | Java Native Interface；Android Java/Kotlin 与 C/C++ 代码互相调用的接口。 | 仅涉及 Android 原生实现层，Web 工程师平时不会直接使用。 |
| **React Component** | 返回 React Element 的函数或类。 | 与 Web React 的组件概念相同。 |
| **React Composite Component** | 继续渲染其它自定义 React 组件或 Host Component 的组件。 | 类似业务组件、布局组件。 |
| **React Host Component** | 最终由宿主平台视图实现的 React 组件，如 RN 的 `<View>` / `<Text>`。 | Web 常见 Host Component 是 `<div>` / `<p>`；RN 对应原生 View/Text。 |
| **React Element Tree** | JavaScript 中由 React Element 构成的描述树；Element 是普通 JS 对象，包含 props、样式和 children。 | 它描述“要显示什么”，不是直接绘制的屏幕像素。 |
| **React Native Framework** | 在 React Native 之上收集路由、构建、发布等生产工具的一套框架。 | Expo 是此类框架之一，类似 Web React 生态的上层框架角色。 |
| **React Shadow Tree / Shadow Node** | Fabric 根据 Host Component 创建的 C++ 树与节点，保存 props 和布局信息，供计算和挂载使用。 | 可理解为渲染器内部的中间表示；它不是可直接操作的 DOM。 |
| **Yoga Tree / Yoga Node** | Yoga 布局引擎使用的节点结构，用于计算 Shadow Tree 的尺寸和位置。 | RN Flexbox 的布局计算实现之一；Host Component 可按需决定是否使用 Yoga。 |

## 读这些术语时的边界

- React Element 是 JS 对象；Shadow Node 属于 Renderer 中间结构；Host View 才是 Android/iOS 上真实的原生视图。
- “RN 使用 React”不表示它渲染 HTML。JSX 和 props 心智模型可以沿用，DOM/CSS/Web API 则要换成 RN 与平台能力。
- JSI、JNI、Fabric、Yoga 是不同层面的技术：互操作、Android 桥接、渲染器和布局引擎，不应当作同义词使用。
