## 新架构解决什么问题

**New Architecture（新架构）**是 React Native 对内部渲染与原生通信方式的一系列重构，主要包含 **Fabric** 新渲染器、**Turbo Native Modules**、Codegen 和新的 JavaScript/原生互操作方式。它为同步布局读取、并发 React 能力和更直接的 JS/原生协作提供基础。

“旧架构”常用 **bridge（桥接层）**异步传递序列化数据；**JSI（JavaScript Interface）**则让 JavaScript 与 C++ 对象建立更直接的引用关系，从而减少传输大量数据时的序列化开销。JSI 是互操作接口，不是单独的 UI 渲染器；渲染由 Fabric 等部分负责。

## 同步布局与避免中间跳动

旧式流程通常在 `onLayout` 后异步测量视图，再更新 tooltip 位置。用户可能先看到 tooltip 出现在旧位置，之后才跳到目标附近：

```tsx
import { useCallback, useRef, useState } from 'react';
import { Text, View } from 'react-native';

type Rect = { x: number; y: number; width: number; height: number };

function TooltipTarget() {
  const targetRef = useRef<View>(null);
  const [targetRect, setTargetRect] = useState<Rect | null>(null);

  const handleLayout = useCallback(() => {
    targetRef.current?.measureInWindow((x, y, width, height) => {
      setTargetRect({ x, y, width, height });
    });
  }, []);

  return (
    <View ref={targetRef} onLayout={handleLayout}>
      <Text>提示内容锚点</Text>
      {targetRect && <Tooltip rect={targetRect} />}
    </View>
  );
}
```

New Architecture 下，可在 `useLayoutEffect` 中读取 layout 并立刻更新同一次 commit 的 UI，避免中间画面：

```tsx
import { useLayoutEffect, useRef, useState } from 'react';
import { Text, View } from 'react-native';

function TooltipTarget() {
  const targetRef = useRef<View>(null);
  const [targetRect, setTargetRect] = useState<Rect | null>(null);

  useLayoutEffect(() => {
    targetRef.current?.measureInWindow((x, y, width, height) => {
      setTargetRect({ x, y, width, height });
    });
  }, []);

  return (
    <View ref={targetRef}>
      <Text>提示内容锚点</Text>
      {targetRect && <Tooltip rect={targetRect} />}
    </View>
  );
}
```

这里的 `Tooltip` 与 `Rect` 是示意组件和类型，重点是测量发生的时机。实际项目需要根据弹层相对哪个窗口定位，并处理尺寸变化与可见状态。

## 并发渲染、自动批处理与 transition

新架构支持 React 18 及之后的并发特性。**Automatic batching（自动批处理）**会把同一轮里多个状态更新合并，减少重复渲染。**Transition（过渡更新）**则给耗时更新较低优先级，让用户输入等紧急更新可以先响应。

下面的示例把滑块变化包进 `startTransition`。渲染很多卡片时，较旧的中间值可以被跳过；`isPending` 可用于显示忙碌状态：

```tsx
import { useState, useTransition } from 'react';
import { ActivityIndicator, Text, View } from 'react-native';
import Slider from '@react-native-community/slider';

function TileCountControl({
  value,
  onValueChange,
}: {
  value: number;
  onValueChange: (value: number) => void;
}) {
  const [isPending, startTransition] = useTransition();

  return (
    <View>
      <Text>渲染 {value} 张卡片</Text>
      <ActivityIndicator animating={isPending} />
      <Slider
        minimumValue={1}
        maximumValue={1000}
        step={1}
        value={value}
        onValueChange={nextValue => {
          startTransition(() => onValueChange(nextValue));
        }}
      />
    </View>
  );
}

export function TileList() {
  const [count, setCount] = useState(1);
  const tiles = generateTileViews(count);

  return (
    <>
      <TileCountControl value={count} onValueChange={setCount} />
      <View>{tiles}</View>
    </>
  );
}
```

`Slider` 来自社区包 `@react-native-community/slider`，不是 React Native core component；`generateTileViews` 表示项目自己的列表生成逻辑。Transition 不会让繁重工作消失，而是帮助 React 安排可中断、低优先级的渲染。

## 新架构开关

新架构从 React Native 0.76 起成为新项目默认值。只有排查不兼容依赖或迁移旧工程时，才需要临时退出；先核实项目与 Expo SDK 的配置约定：

Android 的 `android/gradle.properties`：

```properties
newArchEnabled=false
```

iOS 的 `ios/Podfile` 可在文件主作用域设置：

```ruby
ENV['RCT_NEW_ARCH_ENABLED'] = '0'
```

改动 Podfile 后需重新安装 Pods：

```sh
bundle exec pod install
```

本地 Expo 工程为 SDK 56；若使用 Expo Prebuild / Config Plugin 管理原生目录，不要只在生成后的 `ios` 或 `android` 文件里改开关，应按 SDK 56 项目配置和对应构建流程确认可持续生效的设置。

## 关键名词

- **Renderer（渲染器）**：把 React 描述的界面转换成原生视图更新；New Architecture 使用 Fabric。
- **Commit（提交）**：React 确认一次 UI 更新并准备应用它的阶段；同步测量可以让布局计算和对应更新更协调。
- **Concurrent rendering（并发渲染）**：允许 React 暂停、合并或跳过过时的低优先级渲染工作。
- **JSI**：JavaScript Interface，为 JS 与 C++/原生层提供互操作能力，减少旧式 bridge 的序列化路径。
- **Turbo Native Module**：新架构的原生模块系统，通常结合 Codegen 生成 JS 与原生接口。
- **Codegen**：根据 TypeScript/Flow spec 生成跨 JS 与原生平台的接口代码。
