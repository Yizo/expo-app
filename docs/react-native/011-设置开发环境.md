# 011 设置开发环境（Set Up Your Environment）

**翻页：** [上一页：010 开始使用 React Native（Get Started with React Native）](010-开始使用ReactNative.md) · [目录](README.md) · [下一页：012 集成到现有应用（Integration with Existing Apps）](012-集成到现有应用.md)

**官方页面：** [Set Up Your Environment · React Native](https://reactnative.dev/docs/set-up-your-environment)
**版本范围：** 本页由 RN 0.87 文档（检查日期 2026-09-20）整理。页面中的 Node、JDK、Android SDK/Build Tools 版本是该版指南的快照，不是永久要求。
**源页代码覆盖：** 包含 macOS/Linux/Windows 的安装命令、Android/iOS SDK 配置与环境变量、模拟器准备、Xcode `.xcode.env`/NVM 配置；下文按平台覆盖这些命令主题并重写。

## 先确认是否需要本机配置

RN 官方把框架作为新应用的推荐路线。若使用 Expo 等框架，通常不必手动从空白环境搭建 Android Studio 和 Xcode；若使用无框架 RN 工程、要做原生集成或需要本机编译，就需要安装对应操作系统的工具链。

**JDK**（Java Development Kit）是 Android 原生构建链的基础；**Android SDK** 提供编译平台、命令行工具和模拟器系统镜像；**AVD**（Android Virtual Device）是在开发电脑上运行的虚拟 Android 设备。iOS 的本地构建工具由 Xcode 提供。页面在“unsupported”区域说明：原生 iOS 构建需要 Mac。

## 页面注明的依赖与版本

RN 0.87 页面快照列出 Node.js 22.11.0 或更新版本、JDK 17、Android 15 / API 35 SDK，并选择 Android Build Tools 36.0.0 和最新的 Android SDK Command-line Tools。它还推荐 Watchman 监视文件改动，以改善 Metro 的文件监听表现。具体版本应与项目 RN 版本匹配。

## macOS：Node、Watchman 和 JDK

页面示例使用 Homebrew 安装 Node 与 Watchman，用 Zulu OpenJDK 17 安装 Android 构建需要的 Java。Intel 与 Apple 芯片的 Homebrew 路径可能不同，因此查看安装信息后再在 Finder 中打开实际目录。

```sh
brew install node watchman
brew install --cask zulu@17

# 查看 JDK cask 的安装位置，再按实际版本路径打开
brew info --cask zulu@17
open /opt/homebrew/Caskroom/zulu@17/<实际版本目录>

# 安装后按实际路径设置 Java 主目录
export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home
```

确认 `JAVA_HOME` 指向本机安装位置；如果已使用其他 JDK，页面建议 JDK 17，并提醒更高版本可能导致构建兼容问题。

## Android Studio、SDK 和模拟器

安装 Android Studio 时需要 Android SDK、SDK Platform 和 Android Virtual Device。通过 SDK Manager 安装 RN 工程所需的平台版本与 Build Tools；该版指南提到 Android 15（API 35）、Android SDK Platform 35、Build Tools 36.0.0，以及最新命令行工具。选择 x86_64 或 ARM64 系统镜像时要与开发电脑架构相符。

`ANDROID_HOME` 指向 SDK 根目录；把 emulator 与 platform-tools 目录加入 `PATH` 后，命令行才能找到模拟器和 `adb`。

```sh
# macOS 示例路径；SDK Manager 中显示的真实路径优先
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools"

# 让当前 shell 载入改动并核对配置
source ~/.zprofile
echo "$ANDROID_HOME"
echo "$PATH"
```

可以用插 USB 的 Android 真机开发，也可以在 Android Studio 的 Device/AVD Manager 新建手机虚拟设备并启动。模拟器系统镜像要与项目要求的 Android API 级别对应。

## macOS：iOS 工具链

用 Mac App Store 安装 Xcode，再从 Xcode 设置的 Locations 区域安装 Command Line Tools。需要测试特定 iOS 版本时，从 Xcode Settings 的 Platforms/Components 页面添加相应 Simulator。RN 的 iOS 依赖常由 CocoaPods 管理；`pod install` 相关的具体步骤需要结合项目模板和 RN 版本确认。

`.xcode.env` 可为 Xcode 构建脚本固定 `NODE_BINARY`，让脚本找到合适版本的 Node，而不依赖启动 Xcode 的 shell 恰好加载了什么环境。若通过 NVM 管理 Node，RN 页面建议使 Xcode 的 shell 也能初始化 NVM；示意配置如下：

```sh
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
```

该初始化片段需放在 Xcode 构建脚本能够读取的 shell 配置中，并确保 Xcode 的 Run Script phase 使用预期的 shell。页面也说明 `.xcode.env` 可添加构建需要的其他环境变量。

## Windows：安装工具并设置 SDK 路径

官方页面提供 Chocolatey 安装 Node LTS 与 Microsoft OpenJDK 17 的做法；该命令应在管理员终端运行。Android Studio 安装器需包含 SDK、SDK Platform、AVD；页面还提到 Intel HAXM/Hyper-V 的虚拟化配置，但 HAXM 相关说明可能已随 Android 工具链变化，优先遵循当前 Android Studio 的虚拟化提示。

```powershell
# 仅在计划通过 Chocolatey 管理依赖时使用
choco install -y nodejs-lts microsoft-openjdk17

# 查看本 PowerShell 会话中的环境变量
Get-ChildItem Env:\
```

在 Windows 用户环境变量中创建 `ANDROID_HOME`，该页给出的默认 SDK 路径是 `%LOCALAPPDATA%\Android\Sdk`。再把 `<ANDROID_HOME>\platform-tools` 加到用户 `Path`，打开新的终端并核对变量。SDK Manager 中仍需选 RN 要求的 API 35、Build Tools 36.0.0 和系统镜像。页面指出较新 JDK 若导致 Gradle 无法识别，需要依据兼容要求调整 Gradle wrapper 的 `distributionUrl`；不要为了追新 JDK 而随意升级构建链。

## Linux：Android 工具链

页面建议安装 Node 22.11 或更新版、JDK 17、Android Studio 与 Android 15/API 35 SDK。Node 按发行版官方安装方式处理；Watchman 可按其安装指南从源代码构建。SDK 根路径通常为 `$HOME/Android/Sdk`，把模拟器与 platform-tools 加到 `PATH`：

```sh
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools"

# 按当前 shell 载入并验证；bash/zsh 的配置文件名不同
source "$HOME/.bashrc"
echo "$ANDROID_HOME"
echo "$PATH"
```

Linux 可使用 USB 真机或 AVD。虚拟设备性能依赖硬件虚拟化加速，需要按 Linux 和 CPU 配置。系统的环境变量文件因 shell 而异；把示例放入正确的启动文件后，要新开终端或重新载入。

## 新手如何用这页

1. 先决定走 Expo/其他 RN 框架，还是无框架工程。
2. 选目标平台。iOS 原生编译需要 macOS；Windows/Linux 可配置 Android。
3. 对照项目 RN 版本安装 Node、JDK、SDK 和 Xcode/Android Studio，不要照搬旧教程的版本号。
4. 用 SDK Manager 记录实际 SDK 路径，设置环境变量，并准备真机或模拟器。
5. 安装结束后继续按目标项目的 getting started 指南创建和运行工程。
